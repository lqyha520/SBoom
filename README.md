# 出题工作台

面向教师的出题与排版工作台、内容和会员管理后台，以及独立消费者账号体系的小程序。FastAPI提供统一服务，PostgreSQL保存业务数据，私有文件经过归属和权限校验后访问。

## 环境与启动

需要Python3.12、Node22.12+、pnpm10.14.0和PostgreSQL16。版本与哈希锁文件纳入仓库，更新依赖时同步更新锁文件。

```bash
python -m venv .venv
# 激活该环境后：
python -m pip install --require-hashes -r requirements-dev.lock
pnpm --dir web install --frozen-lockfile
pnpm --dir miniprogram install --frozen-lockfile
```

`admin/node_modules`复用`web/node_modules`。已有链接不要覆盖；全新Linux检出可执行`ln -s ../web/node_modules admin/node_modules`，Windows可使用目录联接或具备权限的符号链接。

首次从`.env.example`创建`.env`，已有文件不要覆盖。至少设置`DATABASE_URL`；应用和测试使用不同实例。日常开发库只需启动根Compose中的`db`服务：

```bash
docker compose up -d db
python -m app.migrations
pnpm --dir web build
pnpm --dir admin build
python run.py
```

默认工作台`http://127.0.0.1:8000/`，后台`/admin/`。模型和生图服务由管理员配置；生产关闭公开API文档，本地开发可访问`/docs`。小程序H5通过`pnpm --dir miniprogram dev:h5`启动，微信构建与发布要求见[小程序README](miniprogram/README.md)。

后台订单与历史对账记录独立于支付配置加载；配置失败可单独刷新，订单在线操作按订单自身支付渠道判断。账单对账仅覆盖微信商户支付，不包含虚拟支付订单。反馈处理发生版本冲突时，通过管理员详情接口读取最新版本，保留本地回复与备注供核对后保存。

推广管理支持同一管理员创建多个活动来源码，以及管理员月度预算和活动累计预算预警。收入可按北京时间实际付款日统计，首次付费与续费分开展示，退款按完成日统计；参考奖励支出包含待核定奖励。预算只提醒，单笔奖励封顶和费用规则只影响之后的新订单，已有订单保留原规则。

注册转化漏斗按同一批注册用户去重统计下单与付费，并按活动对比注册到付费比例和未转化人数。注册日期、管理员与活动筛选统一生效，财务日期口径和明细关键词不改变漏斗；测试订单不计入，付款后退款仍属于曾付费用户。推广管理员可直接查看邀请码绑定、首次付款奖励、等待期、封顶和扣费规则。

漏斗阶段可直接打开对应用户名单，名单与 CSV 导出沿用同一统计时点，并显示活动、渠道及最近下单和付费时间。活动支持名称、渠道、状态筛选和分页；详情展示累计收入、投放成本及参考回报，成本未填或奖励费用未知时不计算回报。推广素材使用后台已配置的图片模型，提供暖调杂志、童趣绘本和极简几何三种风格及画面偏好；生成原画后叠加清晰中文与真实活动码，支持完整预览、修改文案即时排版、PNG 下载和复制文案。生成请求按账号与活动保存，断线后可查询原图，避免重复调用；生成需推广管理的导出权限和有效活动，图片仅当前生成账号可读取。活动落地可选择公开专题或资料。

入口访问漏斗统计访问、开始注册、新注册和后续付费，按访问批次而非独立人数计数，7 天内重复入口复用访问编号。注册归属保留首次来源，后续扫码打开当前活动内容。此功能和指定内容落地依赖新版小程序，后台会显示开始记录时间，旧客户端及更早历史访问无法补齐。微信包位于 `miniprogram/dist/build/mp-weixin`，执行 `pnpm --dir miniprogram check:release` 后仍需通过微信开发者工具上传并发布。

推广管理按“推广概览、活动与推广码、用户与订单、奖励规则”分区；新建与编辑活动使用独立弹窗，活动次要操作收进菜单，停用前明确影响范围。推广结算把工作台、渠道账单、收款资料、提醒和规则分开，超级管理员默认进入申请处理，普通推广管理员默认查看首付奖励；状态和主次按钮采用统一样式。详细扣费在明细中查看，管理员和日期等条件收进更多筛选；支持一键重置及日期范围校验。页签与筛选保存在地址栏，支持刷新和浏览器返回；切换页签保留当前表单草稿，收起申请处理区时键盘焦点返回原入口。

推广结算支持按管理员、状态、日期、支付渠道及订单号筛选，汇总卡片可直接进入对应列表，并按相同范围导出金额以元显示的 Excel（结算汇总、逐单明细、扣费明细）。满等待期的订单可以跨月合并申请，主页面支持连续或批量核对、个人费用按比例计算、申请参考与核定金额对比及差异说明。异常申请可剔除不可结算订单，保留已核对费用并生成关联的新申请，原申请继续留档。

渠道费率未知的订单可先申请对账，但奖励、分渠道合计及完整申请余额显示为“待核对”，仅展示其余订单的已知小计；明确配置的 0% 费率仍正常计算。历史申请在查看和导出时遵循同一口径，原始快照不改写。首付奖励列表的可申请状态由服务端统一判断，较早未完成订单、退款和等待期等阻断条件与实际提交一致。

推广管理员首页按“可申请、处理中、已付款”展示结算，保留等待期与异常入口。超级管理员可选填审核、付款处理目标（1—90 个自然日）；留空表示未约定，审核从提交申请开始计时，付款从审核通过开始计时。目标随新申请保存，旧申请与对应结算单保留提交时规则，超过目标时间显示提示；已付款金额来自登记的实际付款，实际到账需核对收款账户。

管理员可保存加密收款资料，每张结算单保留独立收款快照；超级管理员登记实际付款时间、转账流水号及 PNG/JPEG/PDF 凭证（单份最多 2MB、每单最多 5 份），通过操作时间线和站内提醒跟进处理。推广结算另支持按模板导入微信、安卓虚拟支付及 iOS 虚拟支付的 UTF-8 CSV 账单（最多 5000 行、500KB）；导入只做比对，字段一致后仍须确认采用手续费，不会自动修改订单或退款状态。升级前执行 `python -m app.migrations`；结算凭证存入数据库，收款密文依赖现有加密密钥环，备份恢复时须一并保留。

学习游戏入口为工作台导航「学习游戏」，进入 `/#/games` 游戏中心；可按学科、年龄筛选 32 个游戏，查看玩法与已有进度，从「最近玩过」继续。「益智」分类共 14 款，包括图形数独、数字华容道、点亮星星、汉诺塔、像素拼图、水管连线，以及新加入的七巧板、推箱子、找规律、一笔画、天平称重、颜色排序、镜面对称和找不同；均支持三档难度、玩法说明、提示和本机进度，适配手机操作。推箱子有三章共 72 张不同地图，最少推动 6 至 21 次；七巧板共 27 个轮廓，像素拼图有 30 个主题。通关可直接前往下一关，重试保留本关布局，最后一张仓库地图明确进入回顾。水管与一笔画生成不同路线，汉诺塔后续关改变初始盘面并逐步增加圆盘。古诗、成语、英语和口算采用跨轮内容轮换，时钟支持动手拨针，店长后续营业日更换订单并按需求补货。另有节奏小乐队（跟奏与 8 至 16 拍编曲）、小小农场（六种作物、种植、照顾动物与订单交付）、科学实验室（浮沉、磁铁、混色）、森林救援队（分支故事）、创意画室（自由绘画与 PNG 导出）、动物接接乐（移动篮子与可调速度）、生活小达人（书包、天气与模拟过街）、环保小卫士（海滩、公园、步道清理与动物帮助），可按音乐、自然、探险、创作、反应、生活筛选。益智和这八款体验游戏均只保存本机进度，不上传云存档。原有 `/#/games/little-shop` 等直达链接仍可使用。「小小店长」支持数数量、算总价和找零钱三种难度，包含每日四单营业、库存、结算和店铺升级。游戏不调用模型，访客无需后端即可试玩；访客和工作台账号的本机存档分别保存。分数支持识别、约分、剩余部分与大小比较；诗句和拼写支持局部换位，单词集市交替练习中译英和英译中。数独显示候选，像素拼图按可见线索提示并标记冲突行列；天平后续关卡限制砝码总数，镜面格带图形标识，找规律加入中间缺项。翻牌支持手动收牌，刷新展开中的牌后仍可继续；节奏示范和判定窗口一致，编曲有三种可编辑范例。农场提供包含订单和动物口粮的播种计划、批量浇水收获；接接乐后续增加伙伴和目标，支持按住方向按钮。实验可以先预测并用同材料比较浮沉和磁铁，森林故事支持朗读，画室可单独擦除笔画，过街后续需要等车辆停稳。游戏列表支持按名称和玩法搜索、收藏、查看玩过的游戏以及最近游玩排序；“帮我选一个”遵循当前筛选，优先选择未玩过的游戏。手机列表采用紧凑卡片，进入游戏回到页首，返回时保留筛选并定位原卡片。游戏页提供返回列表、收藏和专注模式，手机提示与撤回工具放在游戏区上方。打开帮助、切出窗口或查看提示时，连续动画和声音暂停；接接乐保留暂停时的落物位置。实现位于 `web/src/games/`。

第二个游戏「机器人闯迷宫」可通过游戏顶部导航切换，或访问 `/#/games/robot-maze` 免登录试玩。包含 36 个渐进关卡，练习指令顺序、相对转向、路线规划和循环；支持积木排序、重复动作编排、逐步执行、暂停和重新尝试。收齐零件并在程序结束时抵达充电站即可通关，自动解锁下一关；独立使用目标积木数内的解法可获得 3 星。关卡、程序和最佳星数自动保存在本机，与小店进度分别存储。

工作台账号登录后可同步游戏云存档，进入时先核对云端版本，游戏中先保存本机再合并短时间内的同步请求。断网保留本机进度，恢复联网或点击「重试同步」后继续；多设备同时修改时选择保留本机或使用云端，不按设备时钟直接覆盖。选用云端前保留一份本机副本，切换账号停止原账号同步。访客进度不自动转入账号。云存档每账号每游戏最多 128 KB，接口按账号隔离、版本检查并支持同一提交重放；不用于成绩、排名或奖励核算。上线前运行 `python -m app.migrations` 升级到 `2026111601`。

结果页的「导出 Word」（窄屏位于「更多导出方式—可编辑 Word」）可下载 DOCX，支持当前试卷或全部合订，以及学生卷、试卷与答案解析、仅答案解析。题干、选项、阅读正文、连线表格、数的分成和比大小均为可编辑文字或表格，保留基本富文本与上下标；答案另起一页。导出沿用题目核对要求，不调用模型。Word 重新分页，装饰背景与自由拖动位置不随文件导出；当前功能面向结构化试卷，不将图片资料自动识别为文字。浏览器使用现有 JSZip 打包，导出时才加载模块。每批最多 100 份、15000 题，源数据不超过 8 MiB。

## 验证

独立测试库监听`127.0.0.1:55432`，使用tmpfs；只允许创建/删除`lc_test_*`一次性数据库。`dev.py`去除继承的`DATABASE_URL`并设置专用测试管理连接，不会停止日常`db`服务。

```bash
python scripts/dev.py up
python scripts/dev.py test
python scripts/dev.py down
python -m ruff check app tests run.py scripts
python -m mypy app run.py scripts
```

测试的 `-n auto` 最多启动4个进程，避免高核数电脑把临时数据库挤满；独立测试库使用1GiB临时数据盘，并限制WAL检查点容量。

三端分别运行`typecheck`、`lint`、`test`、`build`；小程序构建命令为`build:mp-weixin`、`check:mp`和`build:h5`。HTTP契约验证先构建web/admin，再运行`python tests/run_ui_contracts.py`。完整首页浏览器验证还需以 `VITE_API_BASE_URL=/` 构建小程序H5、安装Playwright Chromium，然后运行 `python tests/run_ui_contracts.py --browser`；fixture只使用一次性测试数据，并拦截站外请求。CI还验证锁文件、接口类型、换行、依赖审计和运行镜像。

小程序发现流程和性能回归可分别运行 `python tests/run_ui_contracts.py --suite discovery`、`--suite performance`，也包含在 `--browser` / `--suite all` 中。CI 将它们作为独立测试组运行，失败截图与报告分别保存在 `artifacts/mini-discovery`、`artifacts/mini-performance`；性能组验证加载数量和渲染上限，不替代微信真机性能测试。

接口以本地`/openapi.json`和生成的[shared/api-schema.ts](shared/api-schema.ts)为准。修改输入模型后运行`python scripts/generate_api_types.py`，提交生成差异；无需在README重复维护所有请求体。

工作台浏览器回归使用 `pnpm --dir web test:browser` 和 `pnpm --dir admin test:browser`。小红书本机账号隔离与辅助填入还需运行 `pnpm --dir admin test:xhs-accounts`、`pnpm --dir admin test:xhs-assist`；这些测试拦截外部请求，不登录真实账号，已纳入 CI。

## 数据与权限

后台小红书工作台支持调研、资料与文案制作、素材库、账号排期和效果复盘，使用方式见[小红书工作台说明](docs/admin-xhs-research.md)。采集任务、创作记录和收藏备注按管理员隔离，公开笔记库共享。生成期间编辑或保存新内容后，原结果保留供核对，不会自动覆盖；图片缩略图随素材持久保存，日历按日期范围查询，未排期记录分页。部署这轮改动前运行 `python -m app.migrations` 升级至数据库版本 `2026110201`，再启动新版服务。

小程序用户协议与隐私政策已补充账号、会员退款、资料使用、信息处理、保存期限、未成年人保护与注销规则，联系路径统一为「我的—联系客服」。本次发布前运行 `python -m app.migrations` 升级至数据库版本 `2026110701`：只更新版本为 1、标题未变且正文匹配已知旧默认值的文档；后台编辑过的内容保留，可在「协议与隐私页」自行更新。小程序离线说明与新默认正文一致，登录页同意记录版本同步更新为 `2026-11-07`。

保存超时后会查询原记录，重试沿用原提交并保留之后的新编辑；复盘数据、结论和下一步行动在同一事务中保存。历史版本先与当前编辑对比，覆盖未保存内容前要求确认；生成记录清理遇到本机存储异常时仍能结束本页跟踪，并提示刷新后核对旧请求。发布查重使用持久化摘要索引，复盘基准由数据库计算同账号同阶段的样本中位数。

工作台标题修改默认仅作用于当前试卷，也可选择应用全部；主下载按钮明确导出学生卷，含答案文件从导出选项选择。笔记本短屏自动使用紧凑间距，搭建时可切换专注预览；知识点支持搜索、学期折叠和已选汇总。分页按大题缓存测量，撤销历史共享未变化的题目副本。

后台按工作台、内容资料、用户服务、会员交易、运营配置和系统设置分组，默认展开当前业务组，可搜索菜单并将最多6个常用入口固定到顶部菜单。首页展示平台概况、待办和生成用量；待办直接进入草稿、资料需求、反馈和退款列表。公共习题使用状态标签和组合筛选，筛选与页码保存在网址中，列表和统计独立加载。全屏资料编辑区集中基本信息、教学标签、打印版本和修订稿，角色预览按需展开，支持就地创建分类和创建后继续核对发布。文本与图片模型配置分标签展示，切换时保留草稿。专题支持拖动或上下移排序；编辑表单在关闭、Esc、切换页面与关闭浏览器时检查未保存内容。

后台采用墨绿导航与卡片布局，首页提供资料和内容数据快捷入口，并按服务端真实统计展示最近24小时请求状态分布。资料筛选、批量选择和编辑表单使用统一分组与反馈；入场、悬停和弹窗动效遵循系统“减少动态效果”设置，窄屏保留完整导航与固定保存操作。

顶部搜索支持 Ctrl/Cmd + K 快速打开管理页面，方向键选择、Enter 进入、Esc 关闭；手机端可点搜索图标。未输入关键词时优先展示本次会话的最近访问和常用入口，搜索支持页面名称和分组关键词。编辑弹窗与身份验证期间不响应导航快捷键，页面跳转保留原有未保存内容保护。

侧栏只保留一个「用户服务中心」，通过页面顶部切换资料需求、小程序反馈和出题质量反馈；快捷搜索、待办和原有链接仍可直达对应功能。资料需求用于安排补充内容，小程序反馈支持处理与回复，出题质量反馈用于查看一般及超纲记录。各功能按需加载，保留各自筛选和未保存内容的离开保护。「会员与联系设置」位于「运营配置」，统一维护小程序会员权益说明和客服信息；具体套餐的价格、天数和上架状态在「会员套餐」中管理。

工作台用户与小程序消费者使用独立登录态。服务端检查资料归属、发布状态、VIP与文件访问权限；关闭或禁用账号撤销其会话。Cookie写请求需携带当前账号校验信息，跨账号请求被拒绝。

生成试卷时留在搭建页显示进度，本批处理结束且有可用试卷后切换结果页；全部失败时留在搭建页查看错误或查询原请求。生成请求受并发、每日预算和幂等约束。`GENERATION_DAILY_LIMIT`默认`0`，不限制成功生成次数；设为正数后，按每用户滚动24小时统计成功与进行中的请求，试卷与图片共用额度，失败和结果未知的请求不占成功额度。`GENERATION_DAILY_FAILURE_LIMIT`默认`30`，单独限制滚动24小时内失败、结果未知及心跳过期的请求，设为`0`可关闭失败次数限制。批量出图建议显式设为`0`，避免服务商零星故障累计后封锁正常生成；工作台遇到限流立即暂停后续图片，连续3张未完成也暂停，已发出的请求继续收取，已成功图片保留。模型冷却与并发保护继续生效。失败调用仍可能消耗模型费用和已配置的全站预算。流式中断或状态未知时应通过原请求标识恢复，不能无条件重发收费请求。浏览器草稿和历史按账号隔离并执行保留策略，保存失败需先导出保留副本。新建与重设密码至少8位，历史6位密码仍可登录并透明升级到60万次PBKDF2。

配置从[.env.example](.env.example)及[生产环境示例](deploy/.env.production.example)开始。生产保持`DB_AUTO_MIGRATE=false`，发布前单独迁移；provider默认禁止内网地址（`PROVIDER_ALLOW_PRIVATE=false`）。签名密钥和带编号的加密密钥环分别管理，禁止直接替换旧密钥而丢失历史密文解密能力。

出题提示词提供年级、科目、题数、知识点、难度和对应人教版教材册次，题型使用中文名称。基础、标准、提升分别约束提示程度、独立运用和方法迁移，不以超纲或冗长题干提高难度。选择、应用、阅读、配对等题型各有教学要求，保留用户指定的专项与数值限制；明确的低年级凑十练习使用相应数值边界，不强制凑够考法种数。方法填空可展示待补步骤，完整答案与解析分离；提示词和校验使用同一方法填空范围。整卷、单题、流式及补题使用相同的出题条件。

教材目录唯一来源为 `app/data/pep_catalog.json`，按人教社官方当前公开册次逐册核对；英语只用 PEP 三年级起点。目录保存官方资源号、核对日期、单元页码与细分项来源页，资源号中的年份不冒充出版版次。旧范围文件已移除，历史数据库知识点停用且不再接受编辑，不改写历史试卷。当前目录的 32 册、250 个单元均已标记核实，并通过完整性检查；后续新增的 `pending` 册次不提供知识点，也不使用旧清单兜底。目录更新上线前必须通过 `python scripts/check_pep_catalog.py --require-complete`。

接口字段区分题干与解析：计算题题干不含结果，填空题使用简短题干，解题步骤放解析。校验兼容全角数字和运算符，仍拦截错误答案。批量和单题生成缺题时返回 `422 generation_incomplete`，`partial_sections` 保留有效题目及具体剔除原因；同一请求查询或重放不重新计费。工作台将缺题试卷保留为待完成，手动补齐只请求缺少的题（阅读题整篇重生成，避免混入不同文章）。

所有支持的年级、知识点和题型的新出题请求统一调用模型；题干、答案与解析均由模型生成，本地程序只做校验、筛选与结果整理，不随机编题，也不在模型失败时用本地题目兜底。历史标签不再静默改写成当前教材标签，知识点自由输入保持原意。缺题时仅在既有预算内请求模型补齐，仍不足则明确提示；原请求查询与重放不重复调用模型。

后台「模型配置」的文本与图片服务各支持最多 8 个模型，独立设置地址、模型 ID、密钥、超时及输出参数；列表顺序就是调用优先级，可新增、移除、上下移动和停用。原单模型配置会作为首项保留，空密钥仅保留同一配置 ID 已保存的密钥；更换接口来源须重新填密钥。保存空列表、全部停用或清除文本配置后，不会重新启用 `.env` 模型。

生成等待时限以后台模型配置为唯一来源：前台发送前读取 `/api/v1/generation/options`，后台根据候选超时、有限补题、复核与本地处理计算任务上限，前台另留 30 秒接收结果，不再固定使用 300/630 秒。总任务仍受 `GENERATION_LEASE_SECONDS` 安全上限约束；配置在读取与发送之间变化时，服务端在调用模型前拒绝旧版本。同一原请求的结果重放不受配置更新影响。新任务直接读数据库并固定配置快照，多 worker 立即生效；在途任务的补题和复核沿用开始时配置。

文本配置可选择省略采样参数及使用 `max_completion_tokens`，以兼容不同模型。后台保留快速连接测试，并提供按实际调用参数执行的小型 JSON 测试（最多输出 1024 token，可能计费）。按候选配置 ID 展示成功率、平均耗时、失败和备用调用次数；连续失败默认 2 次后冷却 30 秒，跨 worker 只放行一次恢复探测，配置更新自动使用新的健康状态，可通过 `PROVIDER_FAILURE_THRESHOLD` / `PROVIDER_COOLDOWN_SECONDS` 调整。供应商超时仍可能计费，不会反复重试同一候选；全部候选失败时保留截断响应中可校验的完整大题，不拼接不同模型的原始 JSON。

每个文本模型可单独设置「深度思考」。默认沿用供应商设置；Sage、Qwen 等支持 `chat_template_kwargs.enable_thinking` 的接口可选择关闭，出题、补题、解析复核、流式和后台测试都会使用该配置，答案解析仍按原流程生成。该参数不适用于所有供应商，修改后应使用真实 JSON 测试验证兼容性。模型推理也可能占用输出额度；仅有推理内容而正文为空时，截断提示会明确指出推理阶段耗尽额度。日志只记录推理 token 数和字符数，不记录推理正文，也不会将推理内容冒充最终题目。

本次模型运行策略使用数据库版本 `2026102701`（新增候选健康状态表），升级前运行 `python -m app.migrations`。Nginx 示例的网络兜底时限已放宽，使用已有反向代理配置的部署需同步检查，避免代理先于后台中断长请求。

配置编辑直接读取最新版本；保存多模型列表须携带 GET 返回的 `revision`，清除配置使用 `If-Match` 请求头。旧窗口遇到版本冲突不会覆盖或删除新配置，本地草稿会保留，明确确认后才能载入服务器版本。停用模型不依赖其域名当前是否可用，运行时的公网地址校验仍然保留。文本连接测试须收到有效的非空文本才算成功；错误页、错误事件和空流不再误报连通，参数校验报错不会回显输入密钥。流式生成要求完整结束信号，每次调用只计一次最终有效用量快照。

每次模型操作从首个启用项开始：连接失败、上游拒绝、超时、无效输出或输出截断后立即尝试下一项，不退避等待、不在同一轮重复候选；全部失败才返回错误。配置超时是单个候选的总时限，不能在超时尚未到达时判断一个慢请求失败。取消、本地限流、预算耗尽与安全校验失败不会触发切换。每次尝试独立预留预算并累计调用与上报用量，沿用同一用户请求编号，查询与重放不重新调用。**超时或中断的上游请求仍可能已计费，切换可能产生多次上游费用。** 文本测试连接只测试当前选中项。实验性流式接口在启用多个候选时先缓存完整的一轮输出，丢弃失败残片，避免拼接不同模型结果；因此不保证首字实时返回。

图片异步轮询在同一候选内复用连接，不同来源隔离并逐次校验公网地址；大响应解析和图片转换移到受限工作线程。工作台断线后自动查询原请求，逐步降低频率，离线或后台时暂停；找回结果不会自动生成剩余页面。历史图片的有效 Blob 缓存只读不重写，坏缓存回源修复。连接、取消与恢复边界的验证见[图片出题说明](docs/image-workbench.md)。

新增大题、增加题数及只有配置的旧模板均不填充模拟题；未生成部分保持空白并显示待生成题量，明确点击生成后才请求模型。旧模板快照只恢复已有内容，不猜测缺失题目与答案。锁定题目保留原样；若某份试卷已全部锁定，则提示解锁并保留原卷，不把零模型调用的复制操作记为新生成。查看历史、查询原请求、预览出题说明及下载已有结果都不属于新出题。

结果处理检查字段、题型格式、可确定的计算答案、选择题唯一正确项、配对答案及解析中的独立等式。同卷完全重复题会被剔除，补题受原有调用预算限制；只读取当前账号明确指定的前序分块，不禁止往日基础练习再次出现。不同题型考查同一计算关系、交换加数或使用不同阅读正文可保留；去重保留数学上下标、英文大小写与词间空格，避免误合并。单题替换若与同卷已有题重复，会保留原题并允许重新换题，不自动再次调用模型。

出题提示词统一约束实际 JSON 类型：选择题使用整数索引，配对题使用二维整数数组，数的分成只留一个空；数学强调可复算依据，语文与英语强调充分语境。单题、批量和补题共用教学要求，保留用户指定范围。文本返回拒绝、工具调用、异常结束或错误对象时按失败处理；单题、批量与复核分别校验结果容器，部分有效题继续由逐题校验保留。非流式响应分块限量读取，JSON 解析进入工作线程并计入候选总时限；淘汰的连接池在关停时等待回收。

非流式的单题/批量请求分两阶段生成：先生成题目和简短答案，第一阶段提示词不要求输出 `analysis`；程序校验和有限补题后，每批最多 6 道题补充解析并独立核对答案、歧义和教学适配，每个请求最多 5 批。第二阶段按稳定题目编号回填解析，不改写题干或答案，阅读题跨批次仍携带对应的完整正文，零值答案保留。例如 27 道有效题通常需要 1 次出题和 5 次解析调用；所有调用使用原请求的模型配置快照，累计用量并受现有预算限制，因此可能增加总等待时间与费用。各阶段输出上限直接使用后台 `maxTokens`，不再按题量压低；这降低了长输出被截断的风险，但不能保证模型永不达到上限。

解析与复核温度为 0.1，每批模型链总等待上限为 120 秒，多候选时每项最多 60 秒，为后备项预留机会，管理员配置的更短超时仍优先。任务等待上限覆盖最多 5 批，并在总任务到期前预留 5 秒保存结果。某批超时或协议错误时保留题目及其他成功批次的解析，将该批标为 `unchecked`；预算或配置拒绝时停止后续批次。新解析再次经过本地校验，存在可确定矛盾时只对对应题号重试一次，并将校验依据交给模型重新求解；共享原请求补题预算和总时限，题干、答案及已通过的解析保持不变。预算不足或再次失败时清空错误解析并标为 `needs_review`；修复期间超时仍保留同批已通过的解析。明确错误被剔除并计入缺题，不确定或缺少可靠解析标为 `needs_review`。`quality_status` 和 `quality_issues` 由服务端生成，出题模型不能自行声明复核通过；同一请求查询和重放不重新生成或补解析。两阶段仍在同一请求内完成后返回；生成任务可查询分阶段进度，也可单独补全解析与复核，重试沿用已记录的请求标识。实验性流式接口仍一次生成题目、答案与解析；流式与截断保留的结果未进行独立复核，需核对后使用。

结果页汇总每份试卷的缺题和待核对数量，可直接定位大题，查看选项、阅读正文、答案与解析，修改答案与解析、筛选待核对题并批量锁定。补齐答案和解析后可逐题确认人工核对，也可撤销确认；人工确认独立于模型复核状态，随草稿、历史和归档保存。修改题目内容或阅读正文后需重新核对，单纯调整字体样式保留原状态；修改、确认和锁定支持撤销。同卷重复和缺题不会因人工确认而隐藏，已处理的生成期告警保留在原数据中，不再作为当前待办。模型复核不是正确率保证，实际授课前仍需核对。自动化回归使用构造样例和离线模型响应，覆盖已知错误、误报边界、异常复核协议与请求重放；这些结果不能替代真实模型试卷的人工质量评测。

热门排序使用事务内维护的收藏与下载用户汇总，重复下载不重复计数。升级到数据库版本`2026100501`前执行`python -m app.migrations`，迁移会回填既有记录；迁移完成后再启动新版应用。

受限资料预览在实时授权后复用派生 JPEG，每个服务进程缓存最多 128 张、8 MiB、有效期 5 分钟；文件版本、修改时间或大小改变会重新生成，文件删除立即失效。缓存仅在内存中，服务重启后重新生成，响应仍为 `private, no-store`。公共元数据按键合并并发加载，不同内容互不等待；写入提交清空缓存后，尚未完成的旧加载不能重新填充。

PDF 导出逐页克隆所需卷面并编码 JPEG 字节，保持原有分辨率和画质，释放画布后再处理下一页。浏览器 Performance 中的 `lc.export.layout/rasterize/encode/assemble` 分别记录分页、截图、JPEG 编码及文件合成，每阶段最多保留 60 条，达到上限后清空该阶段旧记录；不记录试卷内容、不自动上传。`generation_stage_duration_seconds` 按 `generate`、`validate_refill`、`review` 统计非流式出题、单个大题校验补题及整批复核耗时，失败/取消也计入；流式仅记录结束后的校验阶段。上述计时不替代真机或真实模型质量评测。

普通试卷批量保存到云端时，默认选择全部试卷并合并为一份 PDF，云端只新增一条记录；也可选择当前试卷或逐份保存。合订本按原顺序拼接各份试卷，保留原始标题、富文本、题目、答案和排版，不自动添加标题编号或修改内容，选择“试卷与答案”时答案紧跟对应试卷。合并文件默认使用第一份的原始标题，不追加份数；可另填文件名，不改变卷面标题。重复保存和上传失败重试复用同一归档；修改内容或渲染版本后生成新版本。每个合集最多 100 份、15000 题、120 页，单份仍最多 1500 题、40 页；快照 2 MiB、PDF 32 MiB、文件包 40 MiB、编码与序列化数据预算 64 MiB，超限停止上传，不保存残缺 PDF。已有逐份归档保持原样。

批量导出每批最多处理 120 页（ZIP 的学生卷与答案均计入），编码数据及序列化副本累计预算 64 MiB，最终下载文件上限 40 MiB；保留每份 40 页限制。超限停止，不下载残卷，可改为逐份下载；不会修改原试卷。预算是保守的数据量保护，不是浏览器进程内存承诺。复核指标的 `success` 表示复核协议处理完成，不代表所有题正确；超时或协议错误后保留题目的降级为 `degraded`，空候选为 `skipped`，未处理异常及取消为 `error`。

2026-11-15 起按用户要求取消部署前的出题评测与人工评分，发布不再自动调用模型做题目验证；常规功能测试、备份、迁移及健康检查保留。

可选的固定真实模型诊断集与只读恢复命令见[评测工具说明](scripts/README.md#质量与真机验收)。默认只查看计划；真实调用须指定专用账号并显式确认付费，继续使用服务端预算与幂等保护。正确率需人工评分，未上报完整 token 用量不输出费用估算，缺题率不冒充误剔除率。真机验收工具检查设备信息、重复测量、阈值与录像/trace 文件；模板或离线测试不能充当真实验收。

CI 由小程序 frontend 任务构建一次同源 H5 并上传，四组浏览器契约测试下载相同产物；纯 HTTP 契约任务不安装前端依赖和浏览器。

公开资料统计、标签和首页内容缓存仅在相关内容事务成功提交后失效，账号、账本、生成任务和反馈等无关写入不会清空缓存。内容事务通过 PostgreSQL `LISTEN/NOTIFY` 通知各进程清空缓存，回滚不发送通知；监听断线后自动重连，重新订阅后清缓存以补偿漏掉的通知，20 秒 TTL 继续兜底。通知异步到达，跨进程存在短暂传播延迟。每个后端进程额外使用一条独立数据库连接，不占请求连接池；`DATABASE_URL` 需连接 PostgreSQL 或支持固定会话的代理，不能使用事务池模式的代理承载监听。维护代码新增公开内容写入时须声明 `db(invalidate_public=True)`。

所有纳入 OpenAPI 的接口成功响应均已声明 JSON 模型或文件/流式类型，覆盖账号、生成、资料库、运营内容、推广结算、经营账本与小红书工具；下载接口区分二进制、分段响应，支付通知保留实际的 204 状态。三端共享类型由 `scripts/generate_api_types.py` 生成，全站契约测试阻止新增接口返回未声明的 `unknown`。用户自定义模板、历史版本快照及动态扩展字段继续兼容原数据。升级需先执行 `python -m app.migrations`（schema `2026111403`）；部署和管理员启用 MFA 需在对应环境实际执行后才生效。
