# 运维变更手册

此文描述待执行的操作流程，不代表已在生产执行。变更前核对目标项目、卷、镜像和回滚条件；不要把环境文件、完整inspect结果或密钥输出到日志。常规发布和加密备份见[部署手册](deploy.md)。

## 密钥环轮换

`SECRET_KEY`用于既有签名及旧格式密文解密，直接更换可能使历史支付payer/openid无法解密。新格式由`ENCRYPTION_KEYS`（编号到密钥的JSON映射）和`ENCRYPTION_ACTIVE_KEY`选择；新写入使用活动编号，读取仍接受密钥环里的旧编号。旧格式迁移期间必须保留原`SECRET_KEY`。

1. 确认一份完整的加密异地备份及恢复演练成功，另在密码管理器保管所有旧密钥。不要仅备份数据库，文件和密钥同样必需。
2. 在仓库外配置文件中将新旧密钥同时加入`ENCRYPTION_KEYS`，先保持旧活动编号，让所有进程加载兼容密钥环。原来只用`SECRET_KEY`的部署保留该值并增加新环。
3. 更新`ENCRYPTION_ACTIVE_KEY`到新编号，重建所有app进程，确认不存在仍写旧密文的旧进程。新旧程序混跑前必须验证它们都理解带编号格式；不兼容旧版不能滚动轮换。
4. 用同一环境运行`python scripts/rotate_encryption.py`。默认只扫描和校验，报告检查数和拟修改数，不输出明文；任何字段不能解密都会失败。生产Docker中使用包含scripts的ops镜像，覆盖其entrypoint为python，并加载同一服务环境及网络；先核对命令解析后的镜像和挂载。
5. 校验通过后执行`python scripts/rotate_encryption.py --apply`。覆盖模型/生图API密钥、小程序openid、订单payer和历史用户模型配置；单事务更新，失败整批回滚。该过程持有账户锁，安排短维护窗口并监控超时。
6. 再运行默认校验，拟修改数应为0；检查登录、模型调用、订单查询与回调解密。支付验证使用沙箱或已存在订单的只读查询，不需要制造真实支付。
7. 旧密钥至少保留到所有旧备份超出保留期，并确认没有旧密文和旧进程。应用回滚版本必须支持该密钥环。单独轮换签名`SECRET_KEY`需安排会话失效窗口，不能与密文迁移混为一步。

## 数据库扩展与收缩迁移

生产`DB_AUTO_MIGRATE=false`，运行进程只校验版本。迁移入口为`python -m app.migrations`；`--check`只验证。首次空库也需要先迁移。迁移与备份互斥和版本校验并不保证任意DDL都能回滚，必须先检查迁移内容。

1. **扩展**：新版本先增加兼容列/表/索引，允许旧版本读写；新增非空字段先可空或带安全默认值，避免一次性锁表回填。大表索引安排专用步骤，不能将`CREATE INDEX CONCURRENTLY`放进普通事务。
2. **备份与预演**：对脱敏或隔离恢复副本执行迁移，记录时长、锁等待和数据校验；完成异地备份。生产目标只来自核实的release配置。
3. **单次迁移**：先启动db，使用待发布镜像运行一次`python -m app.migrations`。然后执行`--check`；失败则停止发布，保留旧app和数据，不自动反向执行DDL。
4. **切换应用**：启动新app，检查readyz、读写和文件链路。发布脚本只在数据库向后兼容时能安全回滚镜像。
5. **回填与观察**：分批回填新增字段，校验计数、校验和及空值，观察至少一个完整业务周期。旧字段仍保留。
6. **收缩**：确认所有旧进程和回滚窗口结束，单独PR移除旧字段/旧写入；先备份。破坏性变更后不要直接回滚旧镜像，事故恢复应先隔离恢复并制定停写切换方案。

维护删除有6小时物理清理宽限，尚有登记引用的文件不能清除。生成请求的幂等墓碑永久保留，清理历史负载时不得删除墓碑，否则旧请求重放可能再次触发收费。

## PostgreSQL大版本或发行版升级

生产当前基线为PostgreSQL16 bookworm，基础镜像digest固定；Dependabot不自动跨PG大版本。Alpine与bookworm的数据卷也不能直接互换。

1. 建立独立升级分支，确认目标版本的扩展、collation、驱动和备份工具兼容性；在CI增加目标版本矩阵，当前版本仍保留。
2. 用当前主版本兼容的`pg_dump`生成逻辑备份，保留角色/权限清单、应用文件、密钥和版本信息，上传加密存储后验证。不要输出密码或把备份留在仓库目录。
3. 创建全新数据卷和隔离的目标版本实例，使用`pg_restore --exit-on-error`恢复；恢复角色/权限时逐项审查，不将生产管理员凭据复制给测试环境。
4. 校验行数、约束、索引、序列值、时区、排序、扩展、应用读写和支付幂等回归，运行`ANALYZE`并比较关键查询延迟。必要时依目标版本要求重建索引，不能把REINDEX当作跨版本迁移。
5. 安排维护窗口停写，做最终备份并再次恢复到新卷，完成校验后切换连接并重启连接池。保留旧实例和旧卷且禁止继续写入。
6. 切换后若出现问题，先停止新实例写入。仅在确认没有新写入或已设计数据回迁方案后切回旧实例；不能直接挂新卷运行旧镜像。
7. 回滚窗口和恢复验证结束后再按保留策略处理旧卷，作为独立操作审批和登记。镜像更新PR必须同步compose、CI数据库版本与本手册。

Compose 已配置 `shared_preload_libraries=pg_stat_statements`、慢查询和锁等待日志。部署后需由数据库管理员在目标业务库执行 `CREATE EXTENSION IF NOT EXISTS pg_stat_statements`，确认扩展与 `pg_stat_statements` 视图可读；预加载设置本身不会创建该视图。扩展权限不授予应用账号，查询统计只向运维开放。

## 敏感产物迁移与清理

`scripts/prune_artifacts.py --dry-run`输出路径、大小、原因和候选，不读取文件内容。默认保留30天；`--archive-loose --apply`仅把过期顶层诊断移入日期目录，`--apply`删除过期诊断。每次操作重新核对解析路径、大小和修改时间；备份、环境、符号链接、密钥文件及本轮P1/P2/P3证据受保护。prune不会自动删除虚拟环境；明确点名的旧依赖目录只有在核对进程与加载模块未引用、当前环境另存后，才能单独清理。

真实`.dump`、`appdata.tar.gz`和secret_key副本必须先迁入仓库外的加密存储，再处理源文件：

1. 在独立私有restic仓库或已批准的加密目录建立副本；Linux目录700、文件600，Windows限制ACL至实际运维账号。加密密码单独保管，目标排除云盘和AI工具索引。
2. 执行仓库完整性检查，在隔离目录试恢复，比较SHA-256清单，并验证数据库、文件、密钥齐全。
3. 登记原路径、加密快照编号、恢复验证时间与操作者。只有这三项齐全，才能人工删除仓库内明文；prune工具不会代做这一步。

Windows本机可使用 `python scripts/secure_archives.py` 预览审查点名的备份清单；`--apply`使用随机32字节主密钥、当前用户DPAPI封装与AES-GCM分块认证加密，目标为 `%LOCALAPPDATA%/LearnCoach/secure-archives/`，密钥文件位于独立的 `keys/archive-key.dpapi`。目录ACL只授予当前用户。每个文件完整解密核对SHA-256，全部文件通过并持久写清单后，再逐个复验并删除源。原路径、密文路径与哈希保存在manifest，不记录密钥或内容。该工具固定白名单为两份点名部署包、`.review/backups/*.dump`和`data/backups/`，不会接触运行中的 `data/secret_key.txt`、业务文件或本轮证据。

恢复使用 `python scripts/secure_archives.py --restore 清单绝对路径 --restore-dir 仓库外新目录`；先重新DPAPI解保护、验证完整密文，再写临时文件并核对磁盘哈希，不覆盖现有文件。DPAPI依赖当前Windows用户配置与系统密钥，换账号或重装系统前须安排受控迁移；本机加密归档不能替代独立密码管理和异地restic备份。非Windows平台会拒绝自动迁移。
