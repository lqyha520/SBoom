# 工作台图片出题

工作台顶部新增「图片出题」。选择年级、科目、知识点和题型，可设置每种题型的题量、难度、画面风格与补充要求，一次选择生成 1～100 张 PNG 习题图。默认同时生成 2 张，完成一张后自动接着生成，支持暂停、继续和恢复历史。「同时生成」按服务端额度可选 1～4 张，偏好按账号保存在本机。题型及题量按每张图片计算，每张上限为 24 道题、5 种题型，单种题型最多 20 题，避免单页文字过密。

常用流程为：选择年级和科目，输入或点选推荐知识点，选择「轻量练习（8 题）」或「综合练习（12 题）」，再点击底部生成按钮。「自定义题型和题量」可展开调整；补充要求及生成说明默认收起。手机通过「出题设置 / 生成结果」切换，生成、恢复历史后自动显示结果；暂停、查询和继续均在结果页操作。

结果区展示本批次的知识点、年级、科目、风格和题量，修改出题设置不会改变已有图片或剩余图片的生成条件。「复用设置」将原批次条件填回表单，不发送请求；「按当前设置新建 N 张」会新建批次并将当前图片保留在本机历史中。完成后可用上一张 / 下一张、缩略图切换，点击图片放大；已完成的图片可点击「重新生成本张」，确认费用提示后只替换当前序号，其他图片和请求保持不变。

后端根据这些条件直接构造图片提示词，由生图模型自主设计完整画面；不经过 JSON 题目生成、HTML 试卷渲染、卷面模板或截图导出。多张生成时，提示词包含总张数和当前序号，要求每张独立成图、变化题目与情境。生成前可预览第一张提示词，结果支持逐张切换、放大、下载和查看每张实际提示词。AI 图片中的文字和题目需要人工核对。

图片提示词按学科和年级筛选题型，后端拒绝不匹配的组合。题量按独立作答任务计算：口算一个算式算一道，阅读统计文章后的问题，连线一组算一道。提示词明确图示数量、分组、减法拿走标记、答案遮蔽、各题型作答空间和难度边界；批次页序分配不同的可选情境与变化方向，但不承诺跨页完全无重复。

在后台文本模型配置中，为已验证支持图片输入的模型开启“用于图片内容检查”。每张新图先落盘，再由首个启用该选项的模型进行一次识图检查，最多90秒，额外计入模型调用与用量预算。检查内容包括实际题型题量、文字符号、可解性、图文对应、知识范围、版面、答案泄露及页内重复；模型报告的题数还会与请求条件比较。页面分别显示“自动检查未发现问题”“自动检查发现疑点”“自动检查未完成”，三者均保留“待人工核对”。自动检查可能误报或漏报，不代表人工审核通过。

检查失败、预算不足或进程中断均保留原图，不自动重新生图或重复识图计费。同一请求重放和状态查询复用已保存结果；中断后找回的图片如无完整检查记录，明确标记待人工核对。未配置检查模型时同样保留原图并显示原因。后台导入保持草稿，发布仍需管理员明确确认。真实图片专项评测使用 `python scripts/evaluate_image_generation.py --directory artifacts/<新目录>`，只在本机一次性库调用模型，保存真实样图、自动检查、重放验证和空白人工评分记录。

「下载和保存范围」默认选择全批，可按原始张序选择起止范围，未完成的图片会跳过。范围同时用于 ZIP、PDF、云端保存和直接添加后台；单张下载仍下载正在查看的图片。

「批量下载图片」将范围内已完成的图片一次打包为 ZIP，解压后可获得每张独立的 PNG 原图。文件名保留原始张序，按批次总张数补齐两位或三位序号，方便排序；暂停批次或恢复历史后也可下载已有图片。单次原图合计最多 128 MB，超过时提示缩小范围。打包在浏览器本地完成，保留原始图片数据，不重新生成或上传图片；打包期间显示进度并防止重复操作，失败后可重试或逐张下载。

「下载 PDF」按原始顺序合并范围内已完成的图片，一张图片一页。每份最多 40 页、32 MB，与云端导入一致；可按 1～40、41～80、81～100 等范围分段保存，图片较大时进一步缩小范围。每页使用适合图片方向的 A4 纸，等比居中、四周至少留白 5 mm，完整保留图片，不裁切、不增加封面或空白页。直接嵌入 PNG，避免截图或 JPEG 压缩造成文字模糊；PDF 在浏览器本地合成，不上传图片、不重复调用生图接口。导出库按需加载。

「保存到云端」供所有工作台账号使用：确认标题、选择文件夹后，将所选范围内已完成的图片按原顺序合成一份 PDF，连同知识点、题型和已指定的题量存入自己的「云端试卷」。未指定题量时不编造题数；修改下一批的设置不会改变本批保存内容。云端保存为私人归档，不会立即公开到小程序，也不受本机缓存或生图结果默认 7 天保留期影响。单份 PDF 上限 32 MB，继续使用云端试卷的数量和存储配额。保存采用账号内稳定的图片组合编号，同一组图片重试或刷新后再次保存复用已有记录，其他范围可以分别保存；先前已成功保存的标题和文件夹保持不变，可在云端库整理。

结果区的「云端试卷」入口支持之后查看、下载和整理记录。管理员可在已保存记录下点击「准备发布到小程序」，选择分类并创建草稿，再前往后台核对、设置访问权限和发布；这一步直接使用云端文件，无需再次合成或上传。已创建草稿的记录显示「查看小程序发布」，刷新后仍能找到。只有后台正式发布后，小程序读者才可查看；普通工作台账号可保存自己的云端资料，不能操作公共发布。

管理员生成图片后，可直接点击预览区的「添加到后台」，确认习题标题、年级、科目并选择分类，将本批已完成的图片合成一份 PDF，保存为公共习题草稿。年级、科目和标题取自这批图片的生成条件，修改左侧下一批的出题条件不会影响它们。保存后点击「查看后台草稿」即可预览、调整权限并发布，无需先下载再手工上传。此操作复用后台 PDF 导入接口，生成预览页并持久保存文件，不再调用生图服务；单份 PDF 上限为 32 MB。保存结果不明确时可先查看后台，同一弹窗重试复用原 PDF，避免重复归档。

## 接口配置

先构建并更新运行服务中的后端、`web/dist` 和 `admin/dist`，再进入管理后台「模型配置 → 图片生成服务」填写：

- 接口地址：自定义 OpenAI 兼容基础地址，例如 `https://example.com/v1`；也接受完整的 `/images/generations` 地址。无路径的域名自动补 `/v1/images/generations`，自定义路径保留。
- 模型：服务商提供的生图模型 ID，与文本模型独立。
- API 密钥：服务端加密保存，读接口不返回明文。留空保留现有密钥；清除生图配置会删除已保存密钥。
- 图片尺寸：必须匹配模型支持的值，默认 `1024x1536`。也可填 `1024x1792`、`1024x1024` 或 `auto`，以接口文档为准。
- 返回格式：默认「自动」，不发送 `response_format`；可显式选择 `b64_json` 或 `url`。
- 生图调用方式：默认「自动识别」，同步接口保持原请求；上游明确要求异步任务时，改用 `async: true` 提交一次。已知支持异步的服务可直接选择「异步任务」，只提交一次生成请求，随后查询同一个任务的结果。
- 超时：单个生图模型为30～600秒，默认300秒；启用图片内容检查后，任务另外预留最多90秒。客户端按服务端返回的任务时限等待；额外网关或反向代理也应允许相应时长。

请求使用 `POST /images/generations`，发送 `model`、`prompt`、`n: 1`、`size`，按配置附加 `response_format`。每张使用独立请求编号，默认最多两个请求同时执行，兼容只支持 `n: 1` 的服务商；完成一张即补入下一张，按原序号展示和下载。单张失败会保留该张错误并继续派发其他图片；遇到暂停或请求记录无法保存时停止派发，已发送的请求仍会完成。未知结果会在剩余图片派发结束后查询原请求，不会自动重复生成；明确失败的图片可在本批其他图片处理完后单独重试。`GET /image-generation/options` 返回账号可用并发上限与默认值，页面不会超过服务端额度或 4 张的工作台上限。支持同步返回的 `data[0].b64_json` 或 `data[0].url`，也支持携带任务编号和 `poll_url` 的异步响应：查询结果可为 `items` 中指定任务的 `results`，或单个 `image.task` 对象的 `data`。查询只向原服务商同一来源发送认证信息，禁止跨来源地址和重定向；轮询、图片下载与解析共用该模型的总超时。单次任务查询最多等待 20 秒；暂时性的查询网络错误、HTTP 429/5xx 最多连续重试两次，仅重试 GET，不重发生成请求。仅未建立连接、明确的请求拒绝或模型不支持错误允许切换下一模型；提交后超时、断线、HTTP 5xx、成品下载失败和无效图片都会停止切换，避免重复计费。

同一候选的提交和轮询复用一个独立连接池，避免每次查询重新握手；不同来源即使解析到同一 IP 也不共享连接。每次请求仍重新检查 DNS 和公网地址，候选结束、超时或取消时关闭连接。大响应 JSON、Base64 解码和图片转换使用最多两个工作线程，不占用事件循环；读取按 64 KiB 分块执行大小限制，转换前释放原始响应引用。上游已出图而本地处理槽位暂忙时，在原超时内等待处理，不因这一次本地繁忙重发上游请求。

同步成品响应可能同时附带 `task_id` 或 `poll_url` 作为追踪元数据。只要 `data[0]` 已有非空图片地址或 Base64，就直接读取成品；只有尚无成品的任务响应才进入轮询，避免已生成图片被误判为失败并重复切换模型。

上游返回 `unsupported_model`、`model_not_found` 等标准错误码时，同步响应和异步任务均归类为「模型不可用」，即使服务商只提供了笼统的「图片生成工具发生错误」提示。原始报错不回显；模型目录列出了某个型号不代表实际生成可用，仍需用真实出题请求验收。

provider默认禁止内网地址（`PROVIDER_ALLOW_PRIVATE=false`），配置前须通过服务端地址校验。URL 图片须为公开 HTTPS 地址。服务端逐次验证并固定公网 IP，不转发 API 密钥给图片下载地址。图片经格式、大小、像素限制及 PNG 转换后交给浏览器，保证下载不依赖远端链接的跨域配置或有效期。

## 请求与结果

- 图片生成与现有题目生成共用登录权限、请求额度、并发限制、请求 ID 去重和结果查询机制。每张占用一次请求额度，并可能分别产生服务商费用。
- 已提交的上游任务编号、查询地址、成品地址及原提示词以加密检查点暂存于未完成请求的 `result_json`，状态接口不返回这些内部数据。页面查询原请求时，服务端用短租约避免并发恢复，只发原任务 GET 或成品下载 GET；最多恢复 8 次，失败后逐步延迟至 5 分钟，单次限时 60 秒。模型来源或型号已变更时停止自动查询；下载不携带服务商密钥。成功后用私有资产元数据替换检查点，保留原请求 ID 和原模型调用次数。恢复记录与生成结果同样受保存期限和清理任务约束，无需新增数据库结构。
- 成品下载最多重试同一 URL 的 GET 三次；真正发生传输失败的地址短暂避开 90 秒，TLS 和 Host 始终保持原域名，重定向仍逐跳校验公网地址。日志只记录阶段、异常类别和成品域名，不记录签名 URL、密钥或提示词。
- 每张图片保留独立请求 ID，同 ID 重放不会再次调用服务商。单张失败会保留该张状态并继续生成剩余页面。超时和网络错误不会自动重发该请求；页面在线且可见时自动查询原请求，间隔从 5 秒逐步增加到 30 秒，最多自动查询 120 轮，仍可手动「查询本次结果」。离线或后台时暂停，恢复网络或回到页面后继续查询；离开页面时取消查询和下载。找回图片后，不会自动重新生成剩余页面；明确失败的图片可在其他页面完成后点击「继续生成剩余 N 张」重试，会使用新的请求 ID，已成功的图片不会重新生成。对已完成图片点击「重新生成本张」也会使用新的请求 ID，并固定原始图片序号；确认后只提交这一张，可能产生新的服务商费用。
- 「暂停后续生成」等待当前图片完成后停止。刷新或重新打开页面只查询已发出的请求，不自动生成剩余图片。用户点击继续后才恢复队列。
- 同一页面切换到试卷搭建再返回，会保留图片。浏览器按账号保存本批出题条件、各张请求 ID 和状态，刷新后可恢复；兼容之前的单张请求记录。图片内容不会存入 localStorage。
- 恢复有效的本机 Blob 缓存只读不重写；空图片、超限数据或请求编号不匹配的缓存会被移除，再查询服务端原结果修复，不重新生成。
- 浏览器图片缓存按账号限制为 256 MiB，写入前在同一事务中计算用量并优先清理较早批次，多窗口写入也受此预算约束。当前批次受保护；清理历史仍不足以容纳新图片时不继续删图，成品在本页保留并提示下载或保存云端。结果区显示缓存用量，提供“清理历史图片缓存”，确认后仅删除非当前批次的图片数据，保留请求 ID 和最近 10 批历史记录。浏览器被清理的图片只有在服务端原结果仍有效时才能恢复。
- 新图片保存为私有文件，`generation_requests.result_json` 只存资产 URL、尺寸和元数据；文件接口校验当前账号。示例及当前部署配置为每用户 `IMAGE_STORAGE_MB=5120`（5 GB），未配置变量的旧部署仍默认 512 MB；此配额独立于 `ARCHIVE_STORAGE_MB` 云端试卷容量，清除浏览器缓存或重建任务不会释放服务器历史图片。入场时每个运行任务预留最多 12 MiB，批量并发出图需留足对应空间。图片与 `GENERATION_RESULT_DAYS`（默认 7 天）同步过期，由独立维护任务分批清理。原请求记录保留以防重复调用。旧 Base64 结果仍可恢复；浏览器 IndexedDB 改存 Blob，localStorage 仅保存请求状态。单张图片限 12 MiB，服务商响应限 18 MiB，最大 1600 万像素。详见 [优化交付记录](optimization-2026-09-21.md)。
- 扩容后需核对联合备份临时空间：`scripts/local_ops.sh` 支持 `OPS_BACKUP_TMPFS_SIZE`（默认 1g）与 `OPS_BACKUP_MEMORY`（默认 2g），在对应运维环境文件中配置。临时空间须覆盖全部试卷、图片及数据库备份，内存上限还需留出备份进程余量，并结合宿主可用内存设置。当前生产已按 20 GB 宿主配置为 12g 临时空间和 16g 内存上限，均为上限而非预先分配；明文备份仍仅保存在容器 tmpfs 中。
- 「添加到后台」仅对管理员显示，保存为草稿；在后台检查并发布后，小程序才可见。普通工作台用户仍可下载 PNG 或 PDF。
- `POST /api/v1/library/import` 接收图片批次的 PDF 和原始出题元数据，生成云端预览并持久保存，不创建公共条目。工作台 Cookie 与账号标识必须匹配，小程序凭证不能调用此接口；重试在同一账号内按图片请求编号序列去重，跨账号保持独立。文件处理复用现有导入并发限制、32 MB 请求体限制和云端归档管线。

- 下载区可开启“下载时添加文字水印”，支持最多 3 行文字、每行 40 个字符，可调节 0%～100% 透明度（数值越大越淡）。布局提供单处文字、整图平铺与斜向平铺；单处文字可选择左上、右上、左下、右下或居中位置。预览与放大图同步显示水印效果，单张 PNG、批量 ZIP 和本地 PDF 下载使用同一设置，并保持原始尺寸。设置按本机账号记住；关闭水印可下载原图，云端保存和后台草稿继续使用原始图片。

## 验证

前端由 `ImageWorkbench.vue` 协调批次与页面状态；`use-image-draft.ts` 管理配置恢复，`use-image-watermark.ts` 管理水印偏好和可取消预览，`use-image-exports.ts` 管理 PNG、ZIP、PDF 下载及账号校验。水印设置与结果预览分别放在 `ImageWatermarkSettings.vue`、`ImageResultPreview.vue`，共用限定在 `.image-workbench` 内的样式。调整其中一项时仍需回归切换账号、刷新恢复、分段导出及手机端布局。

```powershell
python scripts/dev.py test -- tests/test_backend_image_generation.py -v
python scripts/dev.py test -- tests/test_backend_image_cloud.py tests/test_backend_catalog_import.py tests/test_backend_library.py tests/test_backend_body_limit.py -q
pnpm --dir web typecheck
pnpm --dir web test
pnpm --dir web build
pnpm --dir web test:browser -- image-workbench.spec.ts
pnpm --dir admin typecheck
pnpm --dir admin test
pnpm --dir admin build
```

`tests/ui_fixture.py` 为图片出题提供离线测试图片，明确标注 `OFFLINE IMAGE FIXTURE - NOT AI OUTPUT`，不调用任何真实生图接口。实际服务商的模型、尺寸支持、文字质量和费用需在配置真实接口后验收。
