# 用户端小程序性能检查与优化 · 2026-09-19

本轮完成预览组件复用、无消费者下载取消、详情页 PDF 下载取消，以及首页加载占位的布局修正。最值得继续做的是后端生成真正的封面缩略图。现有首屏下载量主要来自整页原图，本轮没有宣称首屏加载速度有明显提升。

## 测量方法与边界

- 使用 `pnpm --dir miniprogram build:h5` 的正式产物，分别保留修改前、修改后的构建。
- 隔离 Chrome，375 × 812，匿名访问真实公开资料；本地静态服务对 JS/CSS/HTML 启用 gzip，API 只代理 GET 到既有 8000 服务，其他方法拒绝。
- 冷加载禁用浏览器缓存，普通网络与弱网各运行 3 次。弱网条件：150 ms 延迟、200,000 B/s 下载、93,750 B/s 上传、CPU 4 倍降速。
- 关闭预览的取消验证单独使用 50,000 B/s 下载、150 ms 延迟。
- LCP/布局偏移来自 PerformanceObserver；组件挂载来自 MutationObserver；请求完成/取消来自浏览器请求事件。没有测量真实用户 INP。
- 以下是本机 H5 实验室数据，不代表微信真机或生产网络。没有修改线上运营内容、登录真实用户、发起支付或提交反馈，也没有重启既有后端。

## 实测结果

| 场景 | 优化前 | 优化后 | 结论 |
| --- | ---: | ---: | --- |
| 原稿从第 1 页连续翻到第 4 页，新增图片容器 | 9 次 | 3 次 | 减少 67%，只挂载新进入预加载范围的页面 |
| 同一场景，销毁图片容器 | 8 次 | 2 次 | 减少 75%，保留仍在使用的相邻页 |
| 预览同时挂载图片容器上限（此场景） | 3 个 | 3 个 | 继续限制为当前页与相邻页 |
| 弱网首页布局偏移，3 次中位数 | 0.0861 | 0.0199 | 减少约 77% |
| 弱网首页 LCP，3 次中位数 | 2.912 秒 | 2.916 秒 | 基本不变，不能认定加载提速 |
| 首页冷加载资源传输量，不含主文档 | 679,137 B | 679,286 B | 基本不变，整页图片仍是主要开销 |
| 1→2→3→4→3→2→1 预览资产请求数 | 6 次 | 6 次 | 原下载池已共享文件，本轮收益主要在组件复用 |
| 首页→习题库→首页，各阶段 GET 数 | 4 / 4 / 4 | 4 / 4 / 4 | 保留原有刷新行为 |

关闭预览时，修改前仍在下载的第 2 页原图又持续了约 4.4 秒才完成；修改后浏览器观察到请求取消。原始时间戳和取消延迟见 `artifacts/mini-perf-2026-09-19/after-interactions.json`。这是指定实验条件下的一次请求生命周期对比，不是所有设备的固定取消耗时。

## 已落实的修改

1. **原稿预览减少重建。** 普通翻页保留相邻图片。缩放过的页面离开时单独重建，可靠清除原生 movable-view 内部的缩放和拖动状态。双指缩放→下一页→上一页的 H5 回归已通过，返回后的缩放与位移均复原。
2. **停止无人使用的下载。** 文件池在最后一个消费者离开、缓存清空或文件失效时调用下载任务的 `abort()`；仍有消费者的共享下载继续运行。已完成文件只释放，不再中止任务。旧请求失败不会移除新请求的文件。
3. **详情页取消待完成的 PDF 下载。** 离开详情页后不再继续下载并迟到打开 PDF；已经打开的原生文档保留文件，避免把打开文档引起的页面隐藏误判为取消。
4. **首页加载过程中减少内容移动。** Banner 骨架与真实 Banner 采用相同尺寸；卡片骨架与真实卡片总高度一致；分类与专题尚未加载时避免提前展示会被后续内容推移的页尾入口。

| 视口宽度 | Banner / 骨架高度 | 习题卡 / 骨架高度 | 横向溢出 |
| --- | --- | --- | --- |
| 320 px | 211.98 / 211.98 px | 249 / 249 px | 无 |
| 375 px | 231.58 / 231.58 px | 261 / 261 px | 无 |
| 430 px | 254.48 / 254.48 px | 261 / 261 px | 无 |

上述几何对比使用当前单 Banner 和真实公开资料；无 Banner、多 Banner、超长动态文案仍可能有不同的内容高度。

## 下一步优先级

### 高：真正的封面缩略图

当前 `thumbnail_url` 指向第 1 页原稿。抽查 8 张图片，尺寸为 1040～1191 × 1471～1684，单张 76,888～261,978 B；实际卡片只显示几十至一百多像素宽。

对同样 8 张原图进行本地、320 px 宽、JPEG 质量 82 的编码实验：

- 原图合计 962,701 B（约 940 KiB）。
- 缩略图合计 83,490 B（约 82 KiB），减少约 91.3%。
- 本轮尚未接入缩略图接口，此数字是样本编码结果，不是已上线节流收益。

建议发布资料时生成缩略图，列表、专题与首页使用缩略图，原稿预览继续使用原图。缩略图接口沿用资料访问权限，资源地址包含版本标识；旧资料提供回退，避免未生成缩略图时空白。验收需覆盖会员权限变化、资料重新发布、生成失败和小屏清晰度。

### 中：公共元数据的短时复用

首页每次返回仍刷新首页内容、分类摘要、专题及习题列表；习题库的元数据已有组件内 5 分钟缓存，搜索也已有 300 ms 防抖。可进一步让纯公开的首页配置和专题在同一会话短时复用，并保留下拉强制刷新。收藏、权限、用户信息和列表内容不能直接套用长时间缓存。验收需确认编辑后刷新生效、切换账号不串数据、写入后的重新读取不复用写入前结果。

### 中：微信真机性能验收

使用低端 Android 与 iPhone，检查冷启动、长列表滚动、连续 20 次翻页、缩放/拖动复位、退出时取消下载、后台再回前台、原生 PDF 打开和内存释放。H5 交互回归及模拟的原生 API 单测不能替代这些检查。

当前微信构建 303 个文件、847.4 KiB，低于 2 MiB 主包限制。现阶段优先压缩图片流量和减少无用工作；随着包体、页面数量和列表数据增长，再依据真机数据安排分包或列表虚拟化。
