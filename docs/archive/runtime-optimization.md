# 运行时优化与验证

## 模型配置

进程内缓存使用互斥刷新和完整快照，空配置同样缓存 60 秒；加载失败不会延长缓存有效期。
保存、清空、启动迁移使用 PostgreSQL accounts 域事务锁，保存时从数据库读取待保留密钥，避免其他 worker 的旧缓存覆盖新密钥。
本进程写入完成后立即失效，其他 worker 最迟在 60 秒 TTL 到期后的下一次读取更新。需要立即全局生效时，应等待 TTL 后确认各 worker，不应把进程内失效视作全局广播。

## 日志

默认写标准输出，生产使用 `docker compose --env-file .env.production logs -f app`（在 deploy 目录运行）。
生产 compose 使用 json-file 驱动，单文件 5 MB、最多 3 个文件。
单进程本地运行可设置 `LOG_TO_FILE=true`，继续使用后台日志尾部查看。
`LOG_TO_FILE=true` 与 `WORKERS>1` 不兼容，启动时报错。通过其他进程管理器启动多进程时，也必须保持 `LOG_TO_FILE=false`。
标准输出模式下后台显示查看提示，不读取以前遗留的 server.log。

## 数据库

字典迁移只补缺失约束，不在每次启动时重建已有唯一索引。
反馈提交使用内容域共享锁和用户级事务锁；不同用户可以并行，同一用户的小时限额检查与插入仍然串行。
原有内容域排他事务仍阻止反馈并发进入，保留删除、后台管理和启动迁移的协调边界。
其余试卷、发布、跨域写入锁保持原状，不在没有业务压测数据时全面移除。

## 限流与使用趋势（2026-09-18）

进程内限流按 key、次数上限和窗口分别保存历史，过期清理使用该条目自己的窗口，
避免短窗口接口清理掉注册、反馈等长窗口的有效计数。窗口左边界不计入，拒绝请求不延长窗口。
到期检查使用最小堆，每个条目只保留一个调度项，每次请求最多处理 64 项；
不再在条目超过 10,000 后对每个成功请求扫描全表。

每进程最多保留 10,000 个 key/策略组合。容量耗尽时，新组合返回限流结果，
已有组合继续按原计数处理，不驱逐有效历史。过期容量随后续请求分批回收，
积压较多时可能需要多次请求才能完成清理。多 worker 仍分别计数，不提供全局精确限流。

`GET /api/v1/admin/experience/analytics` 的每日计数和周/月用户去重改为 PostgreSQL 聚合，
API 进程只接收最多 30 条每日统计、1 条用户汇总及两组最多 20 条的排行。
统计继续使用 Asia/Shanghai 的自然日，缺失日期补零；各项统一排除 30 天窗口外及次日以后的事件。
下载失败排行在次数相同时按资料 ID 排序，响应字段保持兼容。

### 可重复基准

```bash
python scripts/bench_runtime.py --baseline 10eaa55 --events 50000
```

Windows 上若 `python` 是 Microsoft Store 占位程序，可使用 `py -3.12`。
脚本遵循 `tests/pg_support.py` 的本地连接与 `lc_test_*` 一次性库限制，
运行结束清理测试数据；`LC_TEST_PG_ADMIN` 可指定本机测试 PostgreSQL。
基准比较指定 Git 版本和当前工作区，并校验有效时间范围内的样本统计结果相同。
仅对可信的本地版本使用 `--baseline`，脚本会执行其中的限流模块和统计函数。

本机 Python 3.12、50,000 条事件、2,000 个模拟用户的样本结果：

| 指标 | 10eaa55 | 优化后 |
| --- | ---: | ---: |
| 趋势统计服务函数中位耗时（7 次） | 230.69 ms | 92.18 ms |
| 单次统计 Python 峰值分配（tracemalloc） | 37.199 MiB | 0.044 MiB |
| 限流饱和场景中位耗时（2,000 次） | 433.80 μs | 0.50 μs |
| 限流饱和场景 P95 | 507.70 μs | 0.50 μs |

限流场景先尝试注册 10,001 个不同 key，再访问已有 key；优化后第 10,001 个被容量限制拒绝。
这是清理阈值附近的热点对比，不能代表普通低流量请求的提升。
耗时未包含 HTTP、鉴权和序列化；内存仅统计 Python 分配，不含 PostgreSQL 内存，结果随机器负载变化。

## CI

web、admin、miniprogram 使用独立 matrix job，关闭 fail-fast；后端测试独立运行。
UI 契约测试下载 web/admin 构建产物，不重复构建，使用独立的一次性 PostgreSQL 测试库。
小程序失败时仍尝试 UI 契约测试；缺少必要 web/admin 产物时明确失败。
如仓库设置了必需检查，需将原 test 检查更新为 backend、三个 frontend matrix 检查和 ui-contracts。
