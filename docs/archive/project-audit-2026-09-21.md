# learn-coach 全项目审查 · 2026-09-21

> 本文保留优化前的审查证据。后续实现、配置及验证见 [优化交付记录](../optimization-2026-09-21.md)。

本次覆盖出题工作台、图片出题、管理后台、小程序、生成与发布、会员与文件交付、数据库、部署和测试。审查包含当前未提交的开发内容。结论是：基础功能和回归覆盖已经较完整，下一轮收益最高的是修复交付与运行可靠性问题、降低图片传输成本，再优化数据量增长后的查询与编辑性能。

以下区分“已复现的问题”“源码确认的行为”和“需要规模测试的优化方向”。没有调用付费模型、实际支付或变更线上资料。数据库复现使用仓库既有的本机一次性 PostgreSQL 测试库。

## 优先处理

### 1. P1：容器健康检查会把依赖异常判断为正常（已复现）

- 位置：[health.py:59](../../app/routers/health.py:59)、[Dockerfile:49](../../Dockerfile:49)。
- 把数据库探针设为失败，`GET /health/detail` 返回 **HTTP 200**，正文为 `status=degraded`、`database=false`。Docker 的检查只调用 `urlopen`，不检查正文，因此仍然成功。
- `len(llm_client._clients) >= 0` 恒为真，不能说明供应商可用或模型已配置。`/readyz` 已有超时及 503 处理，但 Docker 尚未使用它。
- 建议：容器检查接到有明确语义的就绪接口；区分进程存活、数据库就绪、模型配置状态。供应商连通性单独观测，避免每次健康检查产生付费调用。
- 验收：数据库断开、恢复、慢查询三个场景分别出现预期状态码；不能依靠 HTTP 200 搭配错误正文判断失败。

### 2. P1：PDF 导入的最后一步阻塞事件循环（已复现）

- 位置：[catalog.py:138](../../app/routers/catalog.py:138)。
- 导入接口是 `async def`，PDF 处理使用了线程，但最后直接调用同步的 `catalog.create_paper()`；该函数要获取内容域数据库锁并执行查询、写入。
- 在该同步调用注入 200 ms 数据库等待，10 ms 的事件循环探针出现 **200.9 ms** 间隔。这证明等数据库期间，同一 worker 的其他请求会被阻塞；该数字是故障注入结果，不是线上平均耗时。
- 建议：把这一步也放到线程执行，检查其他异步入口是否存在相同遗漏；为 PDF 渲染设置独立并发上限。重复文件应尽可能在渲染前完成查重，减少无效 CPU 和内存开销。
- 验收：模拟慢数据库时健康请求仍能及时处理；并发导入时限制内存和活跃渲染数量，失败可以定位并恢复。

### 3. P1：监控指标随不同 URL 无界增长，而且监控接线不完整（部分已复现）

- 位置：[main.py:153](../../app/main.py:153)、[metrics.py](../../app/metrics.py)。
- 指标直接使用 `request.url.path`。100 个不同的不存在地址，新增 **100 组请求计数标签和 100 组 Histogram 标签**；真实的资料 ID、资产 ID 也会形成不同标签，且不会自动过期。
- 指标收集无条件执行，但 exporter 仅在 `FORCE_HTTPS=true` 时启动。多 worker 各自尝试绑定 9090，未配置多进程指标聚合；LLM、token、连接池等指标已声明，但搜索不到业务侧更新调用。
- 建议：使用 `/papers/{catalog_id}` 这样的路由模板；404 归入固定标签；监控开关与 HTTPS 解耦；接入真实的生成、连接池等待和锁等待指标，明确多 worker 汇总方式。
- 验收：请求任意数量的不同 ID/404，指标标签数仍有界；两 worker 压测结果与采集计数相符；监控能看到生成失败与数据库等待。

### 4. P2：已发布资料无法通过上传接口补传答案（已复现）

- 位置：[catalog.py:154](../../app/routers/catalog.py:154)、[catalog_editions.py:97](../../app/services/catalog_editions.py:97)。
- 对已发布资料调用 `POST /papers/{id}/editions/import?kind=answers`，返回 **422：请确认文件内容与权限后发布此打印版本**。
- 原因：服务层要求 `confirm_publication=true`，上传接口却没有该参数，构造的 `EditionInput` 永远使用默认 false。文件已经经过导入，关联环节才失败。现有“选择归档 → 保存打印版本”路径具备确认项，可以作为临时操作路径。
- 建议：上传界面和接口贯通版本号、发布确认与结果恢复；或者上传后先进入待确认状态，确认后再关联。不能直接删除服务层的发布保护。
- 验收：草稿与已发布资料都能补充答案；未确认时不改变公开版本；已确认时成功；网络重试不重复生成归档。

### 5. P1（部署条件成立时）：服务器编排保留明文入口

- 位置：[docker-compose.server.yml:68](../../deploy/docker-compose.server.yml:68)。
- 仓库服务器方案把应用映射到 `0.0.0.0:33403`，显式设置 `FORCE_HTTPS=false`，文档说明可通过公网 HTTP 直接登录。会话 Cookie 因而不带 Secure；HTTPS 反代到另一台服务器的回源也是 HTTP。
- 建议：公开登录统一走 HTTPS；回源使用加密隧道、TLS 或受控私网，限制应用端口的来源；再启用 Secure Cookie。
- 本次确认的是仓库配置，未核查服务器当前防火墙或部署版本，不能据此断言线上已发生泄露。

## 性能和使用流程

### 6. P2，收益明确：为列表生成真正的封面缩略图

- 位置：[public_catalog.py:19](../../app/services/public_catalog.py:19)。`thumbnail_id` 直接取第 1 页原稿。
- 本次匿名读取本机服务的 5 张封面，原图宽 1040～1191 px，合计 **840,091 B**；本地转成宽 320 px、JPEG 质量 82 后合计 **98,019 B**，减少 **88.3%**。
- 这是样本编码实验，尚未接入业务，不代表首屏时间已经提升。实际可见卡片数量、网络和缓存会影响收益。
- 建议：发布/导入时生成独立缩略图，首页、列表、专题使用小图，阅读原稿继续使用大图。资产地址保留版本信息，访问权限沿用原资料规则。
- 验收：新旧资料均能显示；重发资料和会员状态变化后权限正确；小屏可读；记录弱网首屏资源量和 LCP。

### 7. P2：返回长列表时会串行重拉所有已看过的页

- 位置：[CatalogList.vue:139](../../miniprogram/src/components/CatalogList.vue:139)、[CatalogList.vue:182](../../miniprogram/src/components/CatalogList.vue:182)。
- `preserveWindow` 用现有条目数计算恢复窗口，然后按每次 20 条串行请求。看过 200 条再从详情返回，会为恢复列表发起最多 10 次分页请求，再恢复滚动位置。
- 建议：按账号和筛选条件保留分页窗口；先展示缓存、恢复滚动，再刷新当前页或必要元数据。收藏变化局部更新；上下架、权限改变与切换账号触发适当失效。
- 验收：20/200/1000 条场景返回请求数不会线性增长；滚动位置稳定；账号和权限信息不会串用。

### 8. P2：首页公开配置可短时复用，请求取消仍可继续完善

- 位置：[home/index.vue:71](../../miniprogram/src/pages/home/index.vue:71)、[api.ts](../../miniprogram/src/services/api.ts)。
- 首页每次显示都会重取首页内容、分类汇总和专题；登录后还会请求最近浏览、未读消息。现有 latest-request 防止旧响应覆盖新状态，但普通 API 请求没有暴露底层 `uni.request` 的取消句柄。
- 建议：纯公开配置使用短 TTL 与请求合并，下拉刷新强制失效；离页取消无消费者的 GET。会员信息、个人列表和写操作保持各自的新鲜度规则。
- 验收：首页往返与快速切换筛选不产生重复排队请求；离页后旧请求不影响页面；后台编辑经刷新立即可见。

### 9. P2：生图结果的存储与恢复需要单独设计

- 位置：[image_generation.py:126](../../app/services/image_generation.py:126)、[generation_control.py:126](../../app/services/generation_control.py:126)、[image-batch.ts](../../web/src/image-batch.ts)。
- 图片统一转成 PNG/Base64，完整结果写进 `generation_requests.result_json`，浏览器再保存 JSON 和 Blob。单张允许 12 MiB 图片，Base64 约增加三分之一体积；生成结果存储不走已有试卷文件配额。
- 过期结果清理在每次生成准入事务内进行。图片增多后，大字段写入、恢复响应、备份和清理成本会一起增加。
- 建议：图片进入受权限控制的文件存储，数据库只保存资产标识、尺寸、状态和费用信息；设置总容量配额和定时分批清理；浏览器缓存 Blob，按需加载历史图。
- 验收：连续生成/恢复 10 张大图时测量浏览器峰值内存、数据库增量与恢复流量；过期任务保留防重复扣费信息，文件清理可靠。

### 10. P2：事件写入和全局清理争用内容域锁

- 位置：[mini_experience.py:152](../../app/services/mini_experience.py:152)、[mini_experience.py:170](../../app/services/mini_experience.py:170)、[generation_control.py:78](../../app/services/generation_control.py:78)。
- 浏览记录、活跃/下载事件等使用全站内容域排他锁，和发布、收藏、文件入库共用；每个事件写入还删除全部过期事件。生成准入也同时做过期结果清理。
- 建议：先采集锁等待，再将确实独立的用户事件细化到用户级锁或依赖唯一约束；清理改为独立、限量、可重试任务，避免一次大清理拖慢交互。
- 验收：并发浏览/收藏/发布时测 P95 和锁等待；保留幂等、限额和删除事务的一致性。

### 11. P2：搜索、热度排序和编辑大试卷需要规模基线

- 位置：[public_catalog.py:107](../../app/services/public_catalog.py:107)、[exam.ts:347](../../web/src/stores/exam.ts:347)。
- 搜索使用跨表的 `LOWER(...) LIKE '%关键词%'`，热门排序对候选资料计算收藏/下载计数，分页使用 OFFSET；大数据量下应验证执行计划。普通 B-tree 索引不能解决包含匹配。
- 编辑撤销会克隆整个题目/试卷集合，并重复序列化撤销栈以计算 4 MB 上限；深度 watch 加自动保存也会随题量增长。
- 本机现有公开库只有 **29 份资料**。每接口 3 次串行匿名 GET 的中位耗时：首页配置 4.0 ms、目录汇总 4.6 ms、20 条列表 5.1 ms、热门列表 5.5 ms。这个规模下未观察到接口明显变慢，不能外推并发容量。
- 建议：用 1 万/10 万资料的隔离样本做 EXPLAIN ANALYZE，再决定 trigram 索引、热度汇总或游标分页；前端用大试卷测输入延迟、撤销耗时，再引入增量快照/预计算字节数。
- 当前三个前端已有分块加载，导出库按需加载；微信产物约 **853 KiB**，16 个页面，低于 2 MiB。现阶段图片、请求和阻塞问题优先级更高。

## 功能质量、依赖和维护

### 12. P2：导入/生图资料的权限和内容元数据不完整

- 位置：[catalog_import.py:100](../../app/services/catalog_import.py:100)、[catalog_access.py:36](../../app/services/catalog_access.py:36)、[image-publication.ts](../../web/src/image-publication.ts)。
- PDF 导入的快照没有题目 sections，因此题量为 0、题型列表为空；图片出题转 PDF 后也走这条流程。实测默认“继承题型权限”解析为 `required_view=free, required_download=free`。
- 这不是绕过已设置的 VIP 权限：逐资料设置 VIP 仍然有效，草稿也没有公开。但管理员只配置题型 VIP、以为导入资料会继承时，结果可能与预期不符。
- 建议：没有可继承题型时，明确展示最终的普通用户/VIP 可见范围，要求选择资料权限或采用明确的导入默认策略；保留图片出题的年级、科目、知识点、题型与题量用于检索。
- 图片生成目前验证文件格式/尺寸，不验证图内题干、答案和题量。增加可记录的内容复核状态、答案配套状态和纠错入口；自动 OCR/算术校验可后续接入，不能用图片格式校验替代内容核对。
- 验收：无题型、有题型、单独 VIP 三种路径行为清楚；图片出题元数据能够在发布和检索中保持一致。

### 14. P2：文件清理和备份恢复缺少可执行闭环

- 位置：[paper_library.py:174](../../app/services/paper_library.py:174)、[mini_jobs.py](../../app/services/mini_jobs.py)、[deploy.md:57](../deploy.md:57)。
