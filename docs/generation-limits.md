# 生成数量与资源保护

图片出题采用有限并发，默认同时生成 2 张，完成一张即补入下一张。普通试卷仍按顺序执行。

| 项目 | 当前行为 |
| --- | --- |
| 图片出题 | 每批 1～100 张；默认同时生成 2 张，支持暂停、查询、继续和历史恢复 |
| 普通试卷 | 每批 1～100 份；每个非阅读大题 1～100 题 |
| 普通题型 | 取消每卷最多 10 种的限制；单卷仍与云端存档保持一致，最多 60 个大题、1500 题 |
| 普通生成请求 | 每次最多 30 题、10 个大题；大题自动拆分，响应按原大题 ID 合并，已成功部分保留，补齐只请求缺失部分 |
| 普通答案解析 | 题目和简短答案生成后，每批最多 6 题补解析并核对答案，每请求最多 5 批；某批失败保留题目和其他批次解析，标为待核对 |
| 阅读理解 | 同一篇文章与问题一起生成，每个阅读大题最多 30 题；需要更多可添加多个阅读大题 |
| 单张图片 | 最多 5 种题型、24 题，单题型 20 题，保留排版密度约束 |
| ZIP 下载 | 按选择范围导出 PNG 原图；最多 100 张、原图合计 128 MB，保留原始张序 |
| 图片 PDF / 云端 | 每份最多 40 页、32 MB；在结果区选择起止张数分段下载或保存 |

首次打开一个批次默认选择所有图片。更换范围不会重新生成；每个云端保存范围按有序图片请求 ID 生成稳定编号，同一范围重试不会重复归档，其他范围可以独立保存。未完成的图片跳过。前端与后端仍保留文件大小、存储容量和账号权限检查。

「同时生成」可选择 1～4 张，实际可选上限为 `min(4, GENERATION_USER_CONCURRENCY, GENERATION_GLOBAL_CONCURRENCY)`，由服务端返回。默认配置下可选 1 或 2 张；如接口支持更多并发，可将账号并发配置提高至 4 后重启，页面即可选择最多 4 张。并发偏好按账号保存在本机，不进入图片生成参数，不改变原请求编号或重试识别。旧服务端未返回并发配置时，页面保守使用 1 张。

偶发单张请求失败时保留该张状态并继续生成；遇到限流、账号失效、模型配置变化或连续 3 张未完成时自动暂停后续图片。手动暂停或请求记录无法保存时也停止发送，已发出的请求继续收完。成功取得一张图片会重置连续失败计数。结果按原张序保存、下载，完成顺序不影响排列。未知结果先按原请求查询，成功图片不会重新生成；明确失败的图片在剩余页面完成后可单独重试。多个标签页仍共享服务端账号并发额度，额度暂满时保留进度，用户可稍后继续。

推荐运行配置为：

```dotenv
GENERATION_DAILY_LIMIT=0
GENERATION_GLOBAL_DAILY_TOKENS=0
GENERATION_GLOBAL_DAILY_IMAGES=0
GENERATION_DAILY_FAILURE_LIMIT=0
GENERATION_USER_CONCURRENCY=2
GENERATION_GLOBAL_CONCURRENCY=6
```

前四项的 `0` 代表关闭对应额度，正数启用滚动 24 小时限制，可以单独设置。未显式设置失败次数限制时兼容旧默认 30；批量出图建议配置为 `0`，避免服务商零星错误累计后封锁用户一整天。已有环境变量与 compose 覆盖文件需要一并调整，重启后生效。用量统计、原请求去重、并发限制、任务超时、模型冷却与批次连续失败暂停继续有效，关闭全天限制不会自动重试失败请求。

数量常量集中于 `web/src/generation-limits.ts`；图片批次校验在 `app/models/image_generation.py`，PDF 页数与 `app/services/paper_storage.py` 同步。普通生成 API 的 30 题限制保持不变，答案解析批量大小由 `app/services/generation_policy.py` 定义。文本各阶段输出上限直接使用后台模型配置，不按题量另行压低；分阶段降低单次输出量，但仍可能达到模型上限。所有调用纳入同一原请求的用量与预算，查询原请求不会重新出题或补解析。
