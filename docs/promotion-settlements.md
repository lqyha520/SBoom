# 推广运营与财务中心操作说明

## 模块入口与职责

侧栏分别提供“推广运营”和“财务中心”。推广运营包含推广管理、我的推广收益和奖励规则；会员交易保留订单、套餐和卡密入口。

财务中心提供七个独立页面：

| 页面 | 用途 |
| --- | --- |
| 财务工作台 | 汇总待对账、对账中、待审核、待付款、未结束异议和异常奖励，点击待办进入对应筛选；查看财务处理消息。 |
| 结算管理 | 核对订单费用、制单、审核、查询结算记录、处理异议和提醒。 |
| 付款管理 | 创建付款批次、导出付款清单、预览并登记实际转账回单。 |
| 账单对账 | 导入渠道账单和核对微信日账单；页签按已授予权限显示。 |
| 成本台账 | 汇总原活动投入明细，核对成本和凭据，按权限进入原活动。 |
| 月度对账 | 查询、下载和确认月度留档。 |
| 财务设置 | 超级管理员配置独立审核、独立付款规则，进入账号授权管理。 |

财务中心复用原结算单、奖励、账单、投入记录和月度账本，拆分入口不会复制或重新计算历史数据。“我的推广收益”只查询登录人的收益、月度账单、收款资料、提醒和异议，即使登录人为超级管理员也不会在该页面显示其他推广人或审核、付款操作。财务人员进入财务中心处理团队数据，奖励政策在独立“奖励规则”页面维护，其他管理员只读查看。

沿用已有权限编号与授权：费用核对与制单、审核与异议处理、付款登记与批次分别控制办理职责；成本台账要求费用核对查看权限，渠道账单与微信核对分别沿用费用核对和微信账单权限；财务设置仅超级管理员可用。授予财务权限不会同时授予推广活动或会员订单权限。

旧收藏和关联链接仍可使用，地址自动规范化并保留筛选参数：

| 旧地址 | 新页面 |
| --- | --- |
| `#settlements` | 财务人员进入 `#financeSettlements`，普通推广人进入 `#referralEarnings`。 |
| `#settlements?section=monthly` | 财务人员进入 `#financeMonthly`，普通推广人保留个人月度入口。 |
| `#settlements?section=batches` / `bills` / `finance` | 分别进入 `#financePayments` / `#financeBills` / `#financeSettings`，仍检查页面权限。 |
| `#settlements?section=payee` / `rules` | 分别进入个人收款资料 / 独立奖励规则；仅有个人结算权限时，奖励规则保留在个人只读页签。 |
| `#reconciliations` | 进入 `#financeBills?section=wechat`，保留原分页等参数。 |

## 财务成本台账

成本台账按推广管理员、活动、活动或管理员名称、投入日期及有效/作废状态查询，每页 20 条。明细和活动详情使用同一份投入记录，凭据包含日期、金额、备注和版本。财务仅核对成本时可直接查看凭据；拥有推广查看权限才显示“查看活动投入”，进入原活动登记区后，浏览器返回会恢复成本筛选并关闭活动弹层。

日期范围有效投入只计所选日期内的有效明细；此前累计投入只计活动已填写的原累计值；全部累计投入为此前累计值加有效新增明细，标为历史补录的明细不再次叠加。后两项仅受管理员、活动和名称范围影响，不受日期或作废状态筛选影响。未填写原累计投入的活动单独提示，累计金额显示已知小计，避免把未知成本当作零。原累计值已经包含的费用按“历史累计内补录”登记；其有效合计不得超过原累计值。日期范围金额包含有效补录，不能与此前累计直接相加。

“本月投入”按北京时间从本月 1 日至今天查询，“上月投入”查询上月完整自然月，“全部日期”清除日期限制。起始与截止日期并排显示；页面列出结果实际使用的范围和上次读取时间。编辑筛选后尚未查询时，保留旧结果并明确提示；管理员选项读取失败不会隐藏已成功读取的成本记录。无效或超出末页的分页会回到当前范围的最后一页。

“导出当前范围 Excel”要求单独授予“费用核对、制单与成本台账”的导出权限，仅有查看或执行权限不会自动获得导出。文件包括整个已查询范围的成本明细和筛选口径，不受当前分页限制，最多 5000 条；超过时提示缩小范围，不会静默截断。金额以元写入数值单元格，凭据、备注和编号按文本写入，日期范围有效投入、此前累计投入、全部累计已知小计与未知活动数均留在文件中。筛选未查询、正在加载或正在导出时，导出入口不可用。

## 财务检索与关联链接

付款管理可按批次名称或编号、处理中/已完成/已取消状态查询，并在地址中保留筛选及分页。打开的批次编号也保存在地址中，整页刷新或直接访问链接可恢复详情；翻页、调整列表范围不会关闭已打开的详情。详情独立查询并显示批次状态，批次不在当前列表页时明确提示。编号不存在时保留列表与返回入口；关闭详情仅移除批次编号，保留列表范围。

独立月度对账页面将推广人和月份写入地址，方便收藏、刷新及历史返回。个人月度对账仍限定本人，并使用独立的筛选备份。

财务首页显示上次读取时间和当前账号可查看的职责。费用核对、结算审核、付款登记分别提供下一步说明；只有查看权限时显示“只读查看”，办理权限继续由前后端独立校验。

## 个人与财务提醒

“我的推广收益”的异议和提醒只展示本人相关记录；财务中心查看团队处理记录。同一个账号的个人提醒和财务提醒分别保存已读位置，在一个入口标记已读不会同时清空另一个入口。旧账号的两个入口首次沿用原已读位置，后续分别更新。

财务设置有未保存修改时，切换页面会提示确认；取消后保留输入，确认放弃后恢复已保存值。关闭或刷新浏览器也会提示未保存修改。

## 推广奖励和预算

参考奖励尚有费用未知时显示“待核对”；部分订单已知时显示已知小计及待核对笔数。已知小计可以为零，不能把它当作全部订单的最终奖励。最终应付仍以对账审核的结算单为准。

月度预算输入按管理员分别保留草稿，筛选活动、翻页、创建或修改活动、切换管理员以及返回缓存页面不会覆盖未保存的输入。保存使用开始编辑时的预算版本；其他人修改了预算后，保存会提示版本冲突并保留草稿。可复制自己的输入，再用“重新载入预算”获取最新值；放弃未保存输入前会要求确认。关闭或刷新浏览器前会提示尚有未保存预算。

未保存预算同时备份到当前浏览器标签页，按登录账号和预算所属管理员隔离。整页刷新后自动恢复输入与开始编辑时的版本，并明确显示恢复提示；后台版本有变化时展示冲突提示，保存仍由服务端校验版本。保存成功、撤销至原值或明确重新载入后清除备份。浏览器临时存储不可用时仍可编辑、保存，但页面会提示刷新前先保存或复制输入。该备份不包含收款资料，不保证关闭标签页后的恢复。

## 异常奖励

奖励列表显示退款、非首次付款、订单未付款、较早未完成订单等具体阻塞原因。具备会员订单查看权限的管理员可从提示进入相关订单，先查单、同步或关闭未完成订单，再刷新结算记录。等待期、退款状态和首次付费资格由服务端在申请、审核、登记付款时重新校验。

## 最新账单差异

审核和登记付款都检查最新导入的渠道账单及每个账单日最新完成的微信核对结果，包含付款日之后的退款差异。实收、交易号、渠道、退款、日期或已核定手续费存在差异时会阻止操作；付款资料面板列出对应订单和原因，可用“刷新付款资料与账单检查”重新查询。

审核窗口在填写个人费用和税额前显示账单检查，查询尚未完成、失败或存在差异时不能批准。使用“刷新审核账单检查”重新核对后需再次确认费用凭据。审核阶段不强制填写收款账号，非零付款登记阶段仍必须留存。

微信日账单完整保存全部差异，页面分批展示。历史结果如果记录的差异总数与保存明细数不一致，会标记“差异未完整留存”，阻止可能受该日收退款影响的微信结算，包含未保存在前 5000 条中的订单。重新核对同一天并保存完整结果后，按最新结果检查；不会把遗漏当作核对通过。

先核对渠道账单及订单状态，尚未付款的结算单需注明原因作废，重新核对费用并生成、审核结算单。原单的金额、规则和费用快照保留。未导入渠道账单时仍可据实人工核对费用，必须填写核对依据。

## 收款资料与付款登记

非零付款必须留存本结算单的收款资料，并填写实际转账时间。收款人先在“收款资料”保存账号，财务可在结算单中“留存当前收款资料”；页面默认只显示账号尾号。实际付款时间须在结算单创建之后，且不能为未来时间。

“登记付款”记录已经完成的转账，金额须等于最终应付。零元核销无需收款账号或实际转账时间，未抵扣完的负余额继续结转。已付款记录的相同付款凭证和金额可安全重试，不会重复记账，也不会补写或重算历史快照。

## 日期、时效与导出

结算记录可按创建日期或推广款实际付款日期筛选，日期以北京时间计算，截止日期包含当天。实际付款口径沿用关联结算单留存的转账时间，包含关联奖励、申请和调整；历史只有登记时间、未留存实际付款时间的记录不纳入此口径。

处理时效分别显示三类申请，可点击进入对应列表：

- 超过三天未更新：仍在处理的申请连续三天未更新。
- 超过审核目标：从申请创建时间起超过申请快照中的审核天数，且尚未批准。
- 超过付款目标：从结算单批准时间起超过快照中的付款天数，且尚未付款。

未设置处理目标的历史申请不计入目标超时。未更新提醒可与目标超时重叠，不能将三项直接相加。管理员、关键词、渠道和日期范围作用于汇总；状态与时效筛选当前列表。筛选组合可能没有匹配记录，例如按实际付款日期查看尚未付款的超时申请。

Excel 导出沿用当前列表范围，并在“筛选口径”工作表记录日期口径、管理员、关键词、渠道、状态和处理时效，便于复核。

## 接口与性能

结算列表、汇总及 Excel 导出增加 `date_basis=created|paid` 和 `timing=stalled|review_overdue|payout_overdue`（留空表示全部）查询参数。奖励列表的 `eligibility_issue` 提供原因、类型和相关订单号；结算单详情的 `bill_differences` 仅向超级管理员返回。

奖励资格采用批量读取。申请预览、申请详情和重新核算预览使用一致的只读数据库快照；提交及财务写入仍在事务内重新校验、串行保护账本。

## 月度对账单

“月度对账”按推广人和北京时间月份查看期初核定余额、税前奖励、原始调整、个人费用、个税、付款及期末余额，支持 Excel 下载。未审核奖励不计入核定余额；负余额表示后续待抵扣。退款扣回作为新的调整入账；`carry:` 仅结转已有负余额，不重复计作新债项。已批准后作废的结算单反向冲回该次核定奖励、费用与个税，原始调整仍保留。

审核人员可在月份结束后确认留档。留档会校验所核对的预览版本，余额或明细变化时须刷新并重新核对。留档版本不能覆盖，重复留档返回原版本。迟到的转账登记或历史记录归入下一个未留档月份，保留原发生时间，已留档结果与后续期初余额保持一致。未留存转账时间的历史付款按登记时间归集。升级时从原结算单与调整回填事件，重复升级不重复记账。

页面先展示余额摘要，“余额变动明细”可展开核对；下载入口位于标题旁。当前月份仅提供实时预览与下载，留档确认在月份结束后开放。

## 付款批次与回单

“付款批次”可跨页选择最多 200 张已审核待付款结算单。创建时留存每单版本、应付与收款摘要，并检查账单、异议和独立付款规则；一张结算单同时只能处于一个待付款批次。已进入批次的单据应通过批次回单登记；需要单独登记时先取消剩余批次记录。

导出 CSV 含收款人、收款方式、开户行、完整账号与金额。导出前再次检查单据版本与阻塞原因并记录下载审计。收款账号前的单引号用于保持文本格式，导入时兼容此格式。

在银行或渠道完成实际转账后，保留导出列名填写流水号、北京时间 `YYYY-MM-DD HH:mm:ss`、结果（成功 / 失败 / 待确认）与说明，再导入预览。零金额核销可不填实际转账时间，仍须填写核销凭据编号。确认只登记匹配通过的记录；账号、收款人、方式、金额、流水号或时间不符的记录保留待处理。成功记录在事务中再次校验退款、账单和权限；失败记录保留并支持后续成功回单重试。重复导入同一回单返回原登记结果，不重复记账。取消批次只释放未付款记录，已登记付款保留。以上操作均不调用银行或支付渠道转账接口。

批次记录与详情在宽屏并排显示，手机端上下排列。创建成功后收起创建区并定位到详情，关闭详情返回列表。“取消剩余付款批次”需在展开的确认区再次确认后才提交。回单入口显示中文文件选择说明与已读取文件名，内容变动后须重新预览并确认。

## 结算异议

推广人从本人奖励或结算单发起异议，可补充说明、凭据编号以及最多 5 份 PNG / JPEG / PDF 附件（单份 2MB）。同一记录未结束的异议使用原线程继续补充。其他推广人无法查看线程或附件。

审核人员可回复并将异议标记为处理中、已解决或不予采纳。未结束的异议阻止相关审核与付款；结束异议不会修改任何金额。如需更正，先作废未付单或登记有依据的结算调整，再记录处理结果。回复与处理结果保留审计，结算提醒显示异议提交和回复。

异议详情按往来记录展示说明、作者、时间与凭据。在当前异议页面切换记录或关闭详情时，保留尚未提交的回复和凭据编号；发送成功后清空该草稿并显示保存提示。切换页面或刷新浏览器不会保留此临时草稿。

## 推广投入台账与用户质量

活动详情中的“管理推广投入明细”按日期、广告 / 物料 / 其他类别登记投入金额、凭据与备注，可按日期查询，修改使用版本校验。同一草稿提交失败后重试沿用请求编号，响应丢失时也不会重复计入成本；已保存记录的更正使用修改入口。作废记录仍保留，退出成本汇总，可恢复。活动原来的累计投入作为“此前累计投入”，与有效新增明细相加用于累计参考回报。历史累计内补录只补齐凭据，不增加累计；作废补录不调整原累计值，原累计值的更正须另在活动中核对修改。

投入登记区位于历史记录之前。修改记录会定位到表单，可取消修改；新增输入可清空。保存后显示反馈、清空已提交的表单，同时保留日期筛选；活动汇总刷新也保留当前台账状态。

推广概览中的“注册后 30 / 60 / 90 天用户质量”沿用管理员、活动和注册日期范围，按活动展示完成观察的人数、未满窗口人数、付费、续费、退款、净收款和人均净收款。只用已完成窗口的用户计算比例，各自窗口末日后的付款和退款不会混入较短窗口。虚拟支付测试订单排除；续费率为窗口内至少两次成功付款人数除以付费人数。人均净收款仅扣退款，尚未扣奖励、手续费和经营成本。

“观察窗口”默认对比全部窗口，也可单独查看 30、60 或 90 天。手机端可横向滚动统计表，统计口径可按需展开。

## 财务分工与独立复核

管理员授权新增三类独立权限：费用核对与制单、审核与异议处理、付款登记与批次。授予财务权限时自动提供结算查看入口，财务可查看全部推广人的结算，其他业务范围不随之扩大。奖励政策与人工调整仍由超级管理员维护，导出权限需分别授予。

超级管理员在“财务设置”设置独立审核和独立付款，默认为关闭以兼容单人财务。独立审核禁止费用核对人或制单人审核同一张单；独立付款禁止审核人登记同一张单的付款，批次登记同样检查。规则适用于超级管理员，启用前应安排具有对应权限的不同账号。

付款管理中的待付款结算单数量减少时，会自动回到最后一个有效分页，保留剩余结算单的选择入口。

复核设置显示是否有未保存修改。未修改时保存按钮不可用；修改后可保存或“撤销未保存修改”，刷新入口暂不可用，避免覆盖输入。推广页面导航保留键盘操作，在手机端切换页签或调整窗口宽度时自动让当前页签保持可见。


## 付款入口与费用关联（2026-11-12 补充）

结算管理负责订单核费、个人费用和个税审核；“办理付款”跳转到付款管理的指定结算单。付款管理保留单张办理、留存和查阅收款快照、账单与异议检查、上传付款凭证，以及批次导出、回单预览和登记。进入待确认或失败批次的单据只能在原批次登记，单张入口会提供返回原批次的按钮；取消剩余批次后才可重新单张办理。金额必须等于核定应付，非零付款必须填写实际付款时间。

实际费用可填写凭据关联编号，建议“凭据号/费用项”。编号忽略全半角、大小写及空白；同一订单共同费用不能重复编号，同张结算中的个人费用不能再使用共同费用的编号。一个发票的不同费用项使用不同后缀。跨订单的共同费用分摊允许使用相同关联编号，财务须据约定核对总额；系统不会自动根据台账金额分摊或封顶。默认费用规则不能绑定实际凭据，实际凭据在核费阶段关联。

新增投入表单要求填写关联编号，同一编号只能有一条有效投入记录，跨活动重复登记也会被拦截。不同活动分摊使用不同费用项编号并核对分摊合计。台账与扣费可以使用同一关联编号，便于追溯，同一费用在台账登记不会自动从推广奖励中扣除。旧记录未填编号仍兼容，补齐后参与查重；单靠编号不能识别未填写或故意使用不同编号的同一实际费用。

投入选择“历史累计内补录”后只补齐明细，累计不再次增加；有效补录合计不能超过此前累计值。修改活动累计值也必须满足这一约束。部分已经计入的费用需拆为不同费用项登记。旧客户端未传新增字段的修改会保留已有编号和补录标记，避免更正说明时改变统计口径。导出的成本和扣费明细均包含关联编号，成本导出另有累计处理标记。


## 六项流程优化（2026-11-12）

### 成本完整性和导出范围

活动未填写此前累计成本时，新增投入仍只属于已知小计，活动结余与回报率保持待计算；确无历史投入应明确填 0。推广投入明细、活动详情和财务成本台账使用相同口径。推广用户、订单导出使用已完成查询的条件；输入筛选尚未查询时显示提示并禁用导出。

### 付款办理预检

付款管理列表在勾选前检查收款快照、批次占用、最新账单、未处理异议、奖励资格和独立付款规则，显示原因及所属批次链接。不可办理单据不能勾选。跨页选择后再次查询服务端，显示所选总金额和阻塞记录，支持刷新预检与移除阻塞项。创建、导出和登记付款仍在服务端重新校验，预检不承诺锁定后续状态。

### 原始凭据与分摊额度

财务成本台账和推广活动投入区可登记原始凭据。编号、所属推广管理员保存后固定，总额修改须核对版本及填写依据；已用额度高于新总额时拒绝保存。可留存 5 个原始附件（PNG、JPEG、PDF，每个不超过 2MB），重复附件按摘要去重，下载独立校验归属和查看权限。

原始凭据号不能包含斜杠。例如登记 `FP202611001`，在原有投入或共同、个人费用中填写 `FP202611001/广告`、`FP202611001/物料`。编号先按全半角、大小写和空白归一化，再以第一个斜杠前的编号关联原始凭据。关联凭据的所属管理员须与活动或奖励受益人一致。

系统按两种用途分别累计并校验原始总额：

- 成本归集：所有活动的有效投入明细，包含历史累计内补录；补录仍不会重复增加活动累计。
- 奖励扣费：所有订单有效共同费用，加所有已审核或已付款结算单的个人费用。相同凭据跨订单使用不同费用项也一起封顶。

上述两项各自不能超过凭据总额，不将成本台账和扣费相加，也不因登记成本自动扣除奖励。作废投入释放成本额度；作废未付结算释放个人费用额度，但仍有效的订单费用保留。已付款后退款不会自动返还此前已发生的扣费，因此仍占用原始凭据额度。所有额度检查与业务修改共用 accounts 事务锁，超额整次回滚。

历史未登记原始凭据的编号继续兼容，不自动编造总额；补登记时会检查已经关联的全部分摊。财务工作台的月末清单列出未关联原始附件的投入，帮助补齐资料。凭据及附件写入、下载分别沿用推广归属和财务职责；只读授权不允许修改。

### 同周期活动对比

推广概览可展开“同周期活动对比”，按完整日期范围（最长 366 天）比较活动，并自动计算紧邻的前一个等长范围。可按付费人数、已知投入、每位付费用户投入、收款减退款及订单退款比例排序，支持分页和进入活动用户名单。

收入按付款日、退款按完成日、投入按投入日归集，均使用北京时间。投入含有效历史补录；尚有未知历史成本或未补齐发生日期的累计成本时，只显示已知投入，不计算每位付费用户投入。该指标包含续费用户，不是纯新客获客成本。订单退款比例按本期付款订单截至查询时的退款经历计算；不同期间观察时间不同。测试订单不计入，零分母不显示伪造比例。

### 月末核对清单

财务工作台可展开月末清单，默认上月，可切换月份并刷新。清单为实时待办，处理后刷新消除，不覆盖原留档结果：

- 待留档推广人：期末余额非零或月内有核定账本变动，且尚未留档。点击进入指定推广人、指定月份；未结束月份先核对，下月留档。
- 微信待核对日期：本月发生本地微信收款或退款，但最新核对缺失、未完成、有差异或差异未完整留存；点击带入原账单核对日期。当天需等渠道账单生成后处理，不含虚拟支付。
- 待补成本资料：月末前创建的活动，其当前历史成本仍未知，或有效投入未关联到有原始附件的凭据。
- 未结束异议：月末前提交且当前仍未处理完毕的异议，点击进入原记录。

各清单独立分页、显示总数，只返回当前账号具有查看权限的数据；仅微信对账授权的账号不返回团队月账、成本或异议。升级版本为 2026111203，仅新增凭据、附件表及索引，不重算历史奖励、付款或月度留档。附件存于 PostgreSQL，随数据库备份保存。
